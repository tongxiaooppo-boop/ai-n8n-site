附錄｜版本附頁

各模組用到的按鈕與節點名稱，標明實測版本實測 n8n 2.48.4（2026-11-18）・你的畫面可能略有不同

2026-11-18 在 Windows 11、Node 24 環境實測 n8n 2.48.4；Docker 版尚未實測。 以下列出各模組要搜尋的節點與正文使用的英文按鈕名稱，按鈕實際位置均為（待查證）。

M0

節點面板搜尋 Manual Trigger（手動觸發）、Edit Fields (Set)（填寫與整理欄位）。

  • Import from File 用於匯入流程，實際位置（待查證）。
  • Execute workflow 用於執行整條流程，實際位置（待查證）。
  • Executions 用於查看執行紀錄，實際位置（待查證）。
  • 內建範例名稱與入口（待查證），正文以「打開任一個內建範例」操作。
  • Docker 版尚未實測，啟動與執行畫面（待查證）。Windows 安裝 Docker Desktop 需 WSL2。
  • npx 備案已實測，使用 Node.js 24 LTS，Node 26 安裝失敗。啟動警告容器外執行已棄用，未來版本會要求 Docker。
  • 時區使用 GENERIC_TIMEZONE=Asia/Taipei。Docker 指令另設 TZ=Asia/Taipei。Docker 資料留在 n8n_data，npx 資料在家目錄 .n8n。

M1

節點面板搜尋 Manual Trigger 與 Edit Fields (Set)。

  • Import from File、Execute workflow、Executions 實際位置（待查證）。
  • Add Field 用於新增欄位，實際位置（待查證）。
  • Expression 用於將值切換成運算式，實際位置（待查證）。
  • String 與 Number 是欄位型別選項，實際位置（待查證）。
  • Pin data 用於釘選測試資料，釘選與解除釘選控制的實際位置（待查證）。

M2

節點面板搜尋 Manual Trigger、Edit Fields (Set)、Split Out、Filter 與 If。 素材採用 Manual Trigger v1、Edit Fields v3.4、Split Out v1、Filter v2.2 與 If v2.2。

  • Import from File、Execute workflow、Executions 實際位置（待查證）。
  • Mode、JSON 與 JSON Output 用於填入陣列測資，實際位置（待查證）。
  • Fields To Split Out 用於指定陣列欄名，實際位置（待查證）。
  • String、is equal to 與 OR 用於設定自選代號條件，實際位置（待查證）。
  • Add Field、Expression 與 String、Number、Boolean 型別選項，實際位置（待查證）。
  • is true 用於判斷 ok，true 與 false 輸出分支的實際位置（待查證）。
  • JSON 輸出檢視的實際位置（待查證）。

M3

節點面板搜尋 Manual Trigger（手動啟動）、Edit Fields (Set)（填資料與計算）、Split Out（拆陣列）、If（分成兩路）、Filter（留下符合資料）、Remove Duplicates（去重）、Merge（合併兩路）。 素材沿用 M2 的節點版本，新增 Remove Duplicates v2、Merge v3.2。

  • Import from File、Execute workflow、Executions、輸出 JSON 檢視的實際位置（待查證）。
  • Mode、JSON、JSON Output、Fields To Split Out 的實際位置（待查證）。
  • Add Field、Expression、String、Number、Boolean 與 is true、contains 選項的實際位置（待查證）。
  • Include Other Input Fields 用於保留其他輸入欄位，實際位置（待查證）。
  • Remove Items Repeated Within Current Input 比較這次輸入、Remove Items Processed in Previous Executions 比較歷史紀錄、Clear Deduplication History 清除去重歷史；三個操作與比較欄位設定的實際位置（待查證）。
  • Merge 的 Append 前後接起資料，Combine 組合資料；All Possible Combinations 用於故障情境，實際位置（待查證）。
  • Input 1、Input 2 是兩個輸入口，對應素材連線索引 0、1，實際位置（待查證）。

M4

節點面板搜尋 Schedule Trigger（到點啟動）、HTTP Request（依網址取資料）、RSS Read（讀新聞與警報）、Limit（限制筆數）、Filter（篩選）、Remove Duplicates（跨次去重）、Edit Fields (Set)（整理欄位）。 素材使用 Schedule Trigger v1.2、HTTP Request v4.2、RSS Read v1.2、Limit v1；其餘沿用 M3 版本。

  • Import from File、Execute workflow、輸出 JSON 檢視的實際位置（待查證）。
  • Schedule Trigger 每天觸發的時間設定與 Custom (Cron) 輸入欄位，實際位置（待查證）。發票 Cron 已實測匯入與 Publish，實際到點觸發（待查證）。
  • HTTP Request 的 GET、網址輸入與 RSS Read 網址輸入的實際位置（待查證）。
  • Always Output Data 在節點 Settings，讓 0 則結果仍輸出空 Item；實際位置（待查證）。
  • 流程 Settings 的 Timezone 用於檢查 Asia/Taipei，實際位置（待查證），不要和節點 Settings 混用。
  • Publish 用於發布流程，實際位置（待查證）；編輯器按下後是否立即生效（待查證）。指令發布模擬來源後需等幾秒已實測。
  • Executions 用於檢查執行時間與啟動方式；分辨手動執行與排程執行的欄位、標記及實際位置（待查證）。
  • Limit 的 Keep 選 First Items 取前幾筆、Last Items 取最後幾筆，筆數欄位與選項實際位置（待查證）。
  • Remove Items Processed in Previous Executions 與連結值設定、String 的 contains、OR、Add Field、Expression、型別選項的實際位置（待查證）。
  • 電腦睡眠或 n8n 關閉後錯過的排程是否補跑（待查證）。

M5

節點面板搜尋 Execute Workflow Trigger（子流程入口）、Execute Sub-workflow（呼叫子流程；拉進畫布後預設名稱是 Execute Workflow）、Read/Write Files from Disk（讀寫本機檔案）、Convert to File（資料轉成 CSV／XLSX 檔）、Extract from File（檔案轉回資料）、Aggregate（多筆收成一筆）、Telegram（傳訊息）、Google Sheets（試算表）；LINE 用 HTTP Request，憑證用 Header Auth。 素材使用 Execute Workflow Trigger v1.1、Execute Workflow v1.2、Read/Write Files from Disk v1、Convert to File v1.1、Extract from File v1、Aggregate v1、Telegram v1.2、Google Sheets v4.7；其餘沿用 M4 版本。

  • Execute Workflow Trigger 的 Accept all data 用於收下呼叫端全部資料，實際位置（待查證）。
  • Execute Sub-workflow 選流程的清單與「M5 快照寫入」選項，實際位置（待查證）。
  • Read/Write Files from Disk 的 Read、Write 與路徑欄位，實際位置（待查證）。
  • Convert to File 的 CSV、XLSX 格式選項，實際位置（待查證）。
  • Extract from File 的 Exclude Byte Order Mark (BOM)，實際位置（待查證）。
  • Aggregate 的 All Item Data，實際位置（待查證）。
  • Telegram 的 Append n8n Attribution 與 chat ID 欄位，實際位置（待查證）。
  • Credentials 新增位置與 Telegram API、Header Auth 憑證類型，實際位置（待查證）。
  • HTTP Request 選 Header Auth 憑證的位置，實際位置（待查證）。
  • Google Sheets 的 Append Row，以及 Sign in with Google 與 OAuth Redirect URL 的位置，實際位置（待查證）。
  • Schedule Trigger 加第二個時間的位置，實際位置（待查證）。
  • Publish 後已發布標記與流程列表的顯示位置，實際位置（待查證）。
  • Import from File、Executions 沿用前面模組，實際位置（待查證）。
  • Docker 掛載 .n8n-files 的實際效果、容器是否自動建資料夾（待查證）；Windows 不會自動建子資料夾已實測。

M6

節點面板搜尋 HTTP Request（呼叫來源）、Error Trigger（錯誤流程入口）、Stop And Error（讓執行故意失敗）、If（依條件分兩路）、Edit Fields (Set)、Telegram、Limit、Schedule Trigger。 素材使用 HTTP Request v4.2、Error Trigger v1、Stop And Error v1、If v2.2、Edit Fields v3.4、Telegram v1.2、Limit v1、Schedule Trigger v1.2。

  • HTTP Request 的 Options → Timeout（毫秒），實際位置（待查證）。
  • HTTP Request 節點 Settings 的 Retry On Fail、Max Tries、Wait Between Tries，實際位置（待查證）。
  • 流程 Workflow Settings 的 Error Workflow，實際位置（待查證）。
  • Error Trigger 的搜尋名稱與輸出欄位 workflow、execution，實際位置（待查證）。
  • Stop And Error 的錯誤訊息欄位，實際位置（待查證）。
  • If 的 exists 條件，實際位置（待查證）。
  • Publish、Unpublish 按鈕，實際位置（待查證）。
  • Import from File、Executions、Telegram API 憑證沿用前面模組，實際位置（待查證）。

M7

節點面板搜尋 Webhook（流程的門鈴）、Respond to Webhook（把結果回給呼叫端）、Execute Workflow Trigger（子流程入口；拉進畫布後預設名稱是 When Executed by Another Workflow）、Execute Sub-workflow（呼叫子流程；拉進畫布後預設名稱是 Execute Workflow）、Telegram Trigger（收 Bot 新訊息）、Telegram、HTTP Request、If、Filter、Edit Fields (Set)。 素材使用 Webhook v2.2、Respond to Webhook v1.5、Execute Workflow Trigger v1.1、Execute Sub-workflow v1.2、Telegram Trigger v1.2、Telegram v1.2、HTTP Request v4.2、If v2.2、Filter v2.2、Edit Fields v3.4。

  • Webhook 的 Test URL／Production URL 切換，實際位置（待查證）。
  • Webhook 的聽取測試按鈕名稱與位置（待查證）。
  • Webhook 的 HTTP Method、Path，實際位置（待查證）。
  • Webhook 的 Authentication → Header Auth，實際位置（待查證）。
  • Webhook 的 Respond → Using 'Respond to Webhook' Node，實際位置（待查證）。
  • Respond to Webhook 的 Respond With → JSON、Response Code，實際位置（待查證）。
  • Execute Workflow Trigger 的輸入方式（定義輸入欄位、JSON 範例、Accept all data），實際位置（待查證）。
  • Execute Sub-workflow 的 Workflow Inputs，實際位置（待查證）。
  • Header Auth 憑證的 Name、Value，實際位置（待查證）。
  • Telegram Trigger 的 Updates，實際位置（待查證）。
  • WEBHOOK_URL 環境變數的設定方式與重開 n8n 後的實際效果（待查證）。
  • Publish、Import from File、Executions、Always Output Data、Telegram API 憑證沿用前面模組，實際位置（待查證）。

M8

節點面板搜尋 Basic LLM Chain（把提示送出、收回回答的鏈）、Google Gemini Chat Model（回答的模型）、Structured Output Parser（規定回答格式）、Execute Workflow Trigger、Execute Sub-workflow、Read/Write Files from Disk、Extract from File、Aggregate、If、Edit Fields (Set)。 素材使用 Basic LLM Chain v1.9、Google Gemini Chat Model v1.2、Structured Output Parser v1.3、Execute Workflow Trigger v1.1、Execute Sub-workflow v1.2、Read/Write Files from Disk v1、Extract from File v1、Aggregate v1、If v2.2、Edit Fields v3.4。

  • Basic LLM Chain 的 Source for Prompt（選 Define below）、Prompt、Require Specific Output Format，實際位置（待查證）。
  • Basic LLM Chain 的 Chat Messages／System Message 位置，實際位置（待查證）。
  • Google Gemini Chat Model、Structured Output Parser 接到 Basic LLM Chain 下方的 Chat Model、Output Parser 插槽的方式，實際位置（待查證）。
  • Google Gemini Chat Model 的 Model 選單與 Options → Sampling Temperature，實際位置（待查證）。
  • Structured Output Parser 的 Schema Type（Generate From JSON Example）與 Auto-Fix Format（本教材不開：它會再呼叫一次模型、多用額度），實際位置（待查證）。
  • Google Gemini(PaLM) API 憑證的 Host、API Key，實際位置（待查證）。
  • Google AI Studio 建立 API 金鑰的位置，實際位置（待查證）。
  • Import from File、Publish、Executions、Credentials 沿用前面模組，實際位置（待查證）。

M9

節點面板搜尋 Manual Trigger、Read/Write Files from Disk（讀本機檔案）、Extract from File（檔案轉回資料）；早報沿用 M5 的節點。 素材使用 Manual Trigger v1、Read/Write Files from Disk v1、Extract from File v1。實測版本 2.48.4，升級測試 2.48.7。

  • Overview 裡看流程是不是 Published 的位置，實際位置（待查證）。
  • 流程 Workflow Settings 的 Error Workflow，實際位置（待查證）。
  • 從編輯器匯出單一流程（Download）與匯入（Import from File）的位置，實際位置（待查證）。
  • 第一次開新的 n8n 時建立擁有者帳號的畫面，實際畫面（待查證）。
  • Executions 的篩選（狀態、流程），實際位置（待查證）。
  • 指令（2.48.4 實測可用）：export:workflow --backup、export:credentials --backup、import:workflow --separate --input、import:credentials --separate --input、unpublish:workflow --all。update:workflow --active 已棄用。
  • 環境變數：N8N_USER_FOLDER、N8N_ENCRYPTION_KEY、N8N_PORT、N8N_RUNNERS_BROKER_PORT。
  • Docker 版的備份、還原與升級指令尚未實測（待查證）。

選修

節點面板搜尋 AI Agent（自己決定要不要用工具的 AI）、Simple Memory（短期記憶）、Code Tool（畫面上叫 Custom Code Tool，給 Agent 用的小工具）、Chat Trigger（聊天視窗入口）、HTML（用 Extract HTML Content 擷取網頁內容）、Code（寫一小段程式）；另用到 Google Gemini Chat Model、Schedule Trigger、HTTP Request、Edit Fields (Set)、If、Telegram、Limit。 素材使用 AI Agent v3.1、Google Gemini Chat Model v1.2、Simple Memory v1.4、Custom Code Tool v1.3、Chat Trigger v1.4、HTML v1.2、Code v2；其餘沿用前面模組。實測版本 2.48.4（選修 B 的 MCP 實測用另一個資料夾的副本）。以下按鈕與選項實際位置均為（待查證）。

  • AI Agent 下方掛 Chat Model、Memory、Tool 的插槽位置與接法，實際位置（待查證）。
  • AI Agent 的 Prompt（Define below）、System Message、Max Iterations、Return Intermediate Steps 在 Options 裡的位置，實際位置（待查證）。
  • Simple Memory 的 Session ID 選項（從聊天視窗來、自訂）與 Context Window Length，實際位置（待查證）。
  • Custom Code Tool 的名稱與說明欄位；工具節點名稱要用英文（例如 search_books），因為實測取中文名時送給模型的工具名稱會變成「_」，模型分不出是哪個工具。
  • Chat Trigger 的聊天視窗按鈕（在編輯器裡開啟聊天），實際位置（待查證）。
  • HTML 的 Extract HTML Content、CSS Selector、Return Array、Return Value（Attribute），實際位置（待查證）。
  • Code 節點的程式編輯區與 JavaScript 選項，實際位置（待查證）。
  • Settings > Instance-level MCP：Enable MCP access、Connect a client、Server URL、MCP 金鑰與 Revoke access，實際位置與按鈕畫面（待查證）。伺服器網址格式 http://localhost:<埠>/mcp-server/http，要帶 Authorization: Bearer <MCP 金鑰>。
  • 選修 B 副本用 N8N_USER_FOLDER、N8N_PORT=5688、N8N_RUNNERS_BROKER_PORT=5689；第一次開要建立擁有者帳號，畫面（待查證）。
  • Import from File、Publish、Overview、Executions、Credentials 沿用前面模組，實際位置（待查證）。
