主線（M0–M5 照順序，之後照需要挑）

M0｜準備環境

在自己電腦開啟 n8n，跑通第一個流程約 1–2 小時實測 n8n 2.48.4（2026-11-18）・你的畫面可能略有不同

成果與先修

在自己電腦開啟 n8n，執行教材流程並找到一次執行的證據。 沒有先修模組。已經會啟動本機 n8n 的人可以從主線的版本核對與教材檢查流程開始。 準備一台電腦，主線費用 0 元。不用新帳號連接外部服務，首次啟動需建立 n8n 本機擁有者帳號。

白話觀念

n8n 把工作排成一個流程。畫布上的每個節點負責一件事，連線把資料交給下一個節點。Manual Trigger 是手動啟動流程的節點。Edit Fields (Set) 用來填入或整理欄位，本課簡稱「欄位」。按一次執行，就產生一次執行紀錄。第 26 天的 GitHub Actions 在雲端執行，本課先在自己的電腦啟動 n8n，再從畫布觀察資料。

手動 → 假早報 → 顯示文字

素材包

  • main-done.json 是主線教材檢查流程。
  • ex1-done.json 是採買清單完成版。
  • ex2-done.json 是家庭提醒完成版。
  • data-broken.json 是故意壞掉的流程檔：格式是 JSON，但裡面沒有任何節點，供故障驗收匯入。

前三份是流程檔，均可用 Import from File 匯入，這個功能會讀取流程 JSON。位置見版本附頁。

主線：開啟 n8n 跑第一個流程

先跑內建範例，再用固定假資料確認教材流程可以執行。

節點 用途 關鍵設定
手動（Manual Trigger） 啟動教材檢查 手動執行
假早報（Edit Fields (Set)） 提供測試資料 name 為假想甲，close 為 100，usd 為 32.85
顯示文字（Edit Fields (Set)） 顯示教材結果 text 這一格已經寫好，執行看結果就好，M1 會教

環境啟動後，依序做以下共同操作。下面兩個分頁各選一個，完成啟動後回來執行。

  1. 核對自己的版本與版本附頁，打開任一個內建範例，執行一次。內建範例名稱（待查證）。
    你應該看到範例的節點與執行結果，可逐個打開查看。

卡住了？找不到內建範例時先記下版本與畫面，對照版本附頁的待查證項目。

  1. 另開流程，下載並用 Import from File 匯入 main-done.json，再按 Execute workflow 執行整條流程。位置見版本附頁。
    你應該看到手動、假早報、顯示文字共 3 個節點，執行後出現綠色勾勾。

  2. 打開「顯示文字」，查看輸入與輸出。
    你應該看到輸入與輸出各 1 筆，text 為 【測試】今天的早報：假想甲 100 元，美元 32.85。

分頁：Docker Desktop

Docker 版尚未實測，實際執行結果（待查證）。以下使用任務指定的官方啟動指令。

  1. 安裝並啟動 Docker Desktop。Windows 需準備 WSL2，安裝細節參考本頁官方連結。
    你應該看到Docker Desktop 已啟動。

  2. 打開終端機，依序執行以下兩行，保留終端機視窗。

    docker volume create n8n_data
docker run -it --rm --name n8n -p 5678:5678 -e GENERIC_TIMEZONE=Asia/Taipei -e TZ=Asia/Taipei -v n8n_data:/home/node/.n8n docker.n8n.io/n8nio/n8n

    你應該看到建立 n8n_data 後開始輸出 n8n 啟動訊息。

卡住了？啟動失敗時先查看 Docker Desktop 的容器日誌，確認 5678 埠是否被占用。

  1. 開啟 http://localhost:5678，首次啟動時建立本機擁有者帳號，再回到共同操作跑範例與教材檢查流程。
    你應該看到n8n 編輯器，教材檢查流程可輸出指定的 text。

關掉終端機視窗會停止 n8n，資料留在 n8n_data。重新開機後要啟動 Docker Desktop，重跑上面的 docker run 指令。

分頁：npx 備案

此路線已實測，作為短期備案。啟動時會警告「在容器外執行已棄用，未來版本會要求 Docker」。

  1. 安裝 Node.js 24 LTS，在 PowerShell 執行 node --version 核對。
    你應該看到版本以 v24 開頭。

  2. 在 PowerShell 設定台灣時區並啟動 n8n，保留終端機視窗。一般啟動命令為 npx n8n，含時區的寫法如下。
    你應該看到n8n 啟動訊息與容器外執行的棄用警告。

$env:GENERIC_TIMEZONE="Asia/Taipei"
npx n8n

卡住了？安裝失敗時先核對 Node.js 是否為 24 LTS，實測 Node 26 會安裝失敗。

  1. 開啟 http://localhost:5678，建立本機擁有者帳號，再回到共同操作跑範例與教材檢查流程。
    你應該看到n8n 編輯器，教材檢查流程可輸出指定的 text。

資料放在作業系統家目錄的 .n8n 資料夾。關閉啟動終端機會停止服務，重新開機後要重跑時區與啟動指令。

小練習①：採買清單

執行一條把品項與數量組成一行文字的流程。

節點 用途 關鍵設定
手動（Manual Trigger） 啟動清單 手動執行
買米（Edit Fields (Set)） 填入品項 title 為買米，qty 為 1
加上數量（Edit Fields (Set)） 顯示清單 已寫好 line

  1. 匯入 ex1-done.json，打開「買米」確認資料，再執行整條流程。
    你應該看到「加上數量」輸出 1 筆，line 為 買米 × 1。

  2. 刪掉「買米」的 title 欄位，保留 qty，重新執行並記錄 line 實際變成什麼。
    你應該看到輸入只剩數量，輸出的清單文字缺少標題。

卡住了？仍看到買米時先確認刪的是來源節點的欄位，再執行整條流程查看新結果。

  1. 恢復 title 為買米，再執行一次。
    你應該看到line 恢復 買米 × 1。

小練習②：家庭提醒

執行同一條家庭提醒兩次，分辨資料與執行次數。

節點 用途 關鍵設定
手動（Manual Trigger） 啟動提醒 手動執行
家事（Edit Fields (Set)） 填入家事 who 為阿禾，task 為倒垃圾
提醒草稿（Edit Fields (Set)） 組成文字 已寫好 draft

  1. 匯入 ex2-done.json，執行整條流程並檢查「提醒草稿」。
    你應該看到輸出 1 筆，draft 為 提醒阿禾：倒垃圾。

  2. 再執行一次，打開 Executions，這裡可以查看每次執行紀錄。位置見版本附頁。
    你應該看到兩次執行各有自己的時間與 1 筆結果。

卡住了？分不清兩次結果時先比對執行時間，再逐次打開查看，n8n 會保留兩次執行。

看懂執行紀錄

打開 Executions，選剛剛的時間，沿著節點順序查看。記下「假早報」輸出的 name、close、usd，再對照「顯示文字」的輸入與輸出各 1 筆。檢查文字內容也符合預期，綠色勾勾只能告訴你節點有執行成功。

若有失敗，記錄失敗節點與錯誤訊息。匯入破損 JSON 在建立可執行流程前就失敗，驗收時要比對匯入前後的紀錄數量。

驗收

  • 正常。教材檢查流程輸入、輸出各 1 筆，text 與主線指定內容相同。
  • 缺資料。刪除「買米」的 title，記下 line 實際內容，指出缺少標題，恢復後重跑成功。
  • 重複。家庭提醒執行兩次，找到兩筆執行紀錄，每次輸出各 1 筆，能說明還沒有做去重。
  • 故障。用 Import from File 匯入 data-broken.json，看到匯入失敗或畫布上沒有任何節點（實際畫面待查證），說得出原因是檔案裡沒有節點，並確認執行紀錄沒有新增。
  • 變形題。把採買清單改成澆花清單，自己改品項與數量，重跑並說明修改流程設定如何影響新的執行結果。
卡關救援
  • 網頁打不開 → 查看啟動終端機、Docker 容器日誌與埠映射 → 先啟動容器，檢查 5678 是否被其他程式占用並解除衝突 → 重新開啟 http://localhost:5678，確認能進編輯器。
  • npx 安裝失敗 → 查看 node --version 與錯誤原文 → 先改用 Node.js 24 LTS，再重跑啟動指令 → 確認出現啟動訊息且編輯器可開啟。
  • 重新開機後打不開 → 查看 Docker Desktop 與啟動終端機 → 依所選分頁重新啟動 → 再跑一次教材檢查流程，確認文字正確。
  • 匯入失敗 → 查看檔名與 JSON 內容 → 練習時改匯入完成版，將 data-broken.json 留作故障驗收 → 確認畫布出現 3 個節點且可執行。

求助時附 n8n 版本、預期與實際結果、哪個節點、錯誤訊息原文、已經試過什麼。截圖先遮住金鑰和個資。
