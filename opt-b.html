選修 B｜請 Claude 幫你寫流程

透過 n8n 內建 MCP 讓 AI 寫出補貨提醒流程，自己驗收約 2 小時先修：M8實測 n8n 2.48.4（2026-11-18）・你的畫面可能略有不同

成果與先修

讓 AI 在你的副本 n8n 裡幫你做出一條「補貨提醒」流程，然後由你自己驗收：逐個節點說得出用途、改一次門檻、修一次錯、確認沒有被 Publish。 先修 M8（會用 Execute workflow、看 Executions）；M9 第 3 段的「隔離還原」做過會更順，因為這裡開副本的做法一樣。 要準備的帳號：n8n 這端不用新帳號。要有一個「能接 MCP 的 AI 用戶端」（例如 Claude Desktop 或 Claude Code）；哪個方案能用、要不要付費，待查證。沒有也沒關係，第 2 段有免費退路。 費用：n8n 這端 0 元（實測沒有要授權或付費的檢查）；AI 用戶端的費用待查證。時間約 2 小時。

白話觀念

  1. MCP 一句話：一種讓 AI 用戶端「連到別的程式、用它提供的工具」的通用接法。連上 n8n 之後，AI 就能搜尋、建立、驗證、執行你的流程。
  2. n8n 內建 MCP：n8n 2.48.4 自架版本身就有 MCP 伺服器（官方叫 Instance-level MCP），在 Settings > Instance-level MCP 打開（位置見版本附頁，按鈕畫面待查證）。實測連上後，伺服器名稱是「n8n MCP Server」，有 60 多個工具，包含搜尋流程、建立流程、驗證流程、執行流程、Publish／Unpublish、封存流程、列出憑證。
  3. 為什麼不用第三方 n8n-mcp：內建的是官方做的，跟著 n8n 版本更新，不用多裝一個第三方套件。
  4. 範圍：官方說 MCP 預設只看得到「有開放給 MCP」的流程（搜尋除外），而且所有連上來的 AI 用戶端看到的範圍都一樣，沒辦法對不同的 AI 分別設權限。
AI 用戶端 ──(MCP 金鑰)──▶ http://localhost:5688/mcp-server/http ──▶ 副本 n8n
                                                                    └─ 建立流程／驗證／執行（你只驗收）

安全規則（先讀）

⚠️ 先讀這五條再動手。 AI 透過 MCP，能建立、執行、Publish、封存你的流程，也看得到你有哪些憑證（名稱）。

  1. 只在副本打開 MCP：用另一個資料夾（N8N_USER_FOLDER）、另一個埠（N8N_PORT=5688、N8N_RUNNERS_BROKER_PORT=5689）開一個全新的 n8n，正式版不要開。
  2. 副本裡不放真的 Telegram 或 Google 憑證。這一課只做假資料的流程，用不到憑證。
  3. 跟 AI 說清楚不准 Publish；做完自己到 Overview 檢查沒有任何流程被 Publish。
  4. MCP 金鑰當密碼保管：不貼給別人、截圖要遮住；用完回到 Instance-level MCP 關掉，或撤銷（Revoke access）。
  5. 副本第一次開要建立擁有者帳號（M9 學過，畫面待查證）。

第 1 段：開副本、打開 MCP

  1. 開一個新的 PowerShell 視窗，設環境變數並啟動：

    $env:N8N_USER_FOLDER="C:\n8n-mcp-lab"
$env:N8N_PORT="5688"
$env:N8N_RUNNERS_BROKER_PORT="5689"
npx n8n start

    你應該看到n8n 啟動；這個視窗之後的 n8n 都用 C:\n8n-mcp-lab 當家。做法跟 M9 第 3 段一樣，正式版（5678）可以同時開著。

卡住了？「n8n Task Broker's port 5679 is already in use」：沒設 N8N_RUNNERS_BROKER_PORT，被正式版占走了。兩個埠都改好再啟動。

  1. 打開 http://localhost:5688，建立擁有者帳號（畫面待查證）。
    你應該看到一個全新的、空的 n8n：沒有你正式版的流程，也沒有憑證。

  2. 到 Settings > Instance-level MCP，打開 Enable MCP access，建立或取得 MCP 用的金鑰（位置與按鈕畫面待查證，見版本附頁）。把金鑰先複製起來，只放在你自己的記事本，不要貼進對話或流程。
    你應該看到MCP 已啟用，頁面上有 Server URL 和金鑰。伺服器網址長得像 http://localhost:5688/mcp-server/http。

卡住了？網址別填成編輯器網址（http://localhost:5688）。MCP 的網址要加 /mcp-server/http，而且要帶 Authorization: Bearer <MCP 金鑰>。

第 2 段：連上 AI（或用免費退路）

做法 A：連上能接 MCP 的 AI 用戶端

用戶端的畫面與費用都待查證；以下是官方 MCP client examples 頁的寫法。

  • Claude Desktop（用 API 金鑰）：在 claude_desktop_config.json 加一段 mcpServers，借 supergateway 把本機網址轉接過去：

    {
  "mcpServers": {
    "n8n-mcp": {
      "command": "npx",
      "args": [
        "-y", "supergateway",
        "--streamableHttp", "http://localhost:5688/mcp-server/http",
        "--header", "Authorization:Bearer <MCP 金鑰>"
      ]
    }
  }
}

    官方另有一種「Add custom connector」，要填公開網址；本機 localhost 能不能用待查證，教材用上面這種 API 金鑰的做法。

  • Claude Code：

    claude mcp add --transport http n8n-mcp http://localhost:5688/mcp-server/http --header "Authorization: Bearer <MCP 金鑰>"

  • 官方還列了 Gemini CLI、Codex、Cursor、VS Code 等，教材只列名字，不逐一示範。

  • Claude 哪個方案能用 MCP、要不要付費：待查證。

你應該看到AI 用戶端列出「n8n MCP Server」，能看到一批工具。請 AI 先「列出你能用的 n8n 工具」，確認有連上。

做法 B（免費退路）：沒有能接 MCP 的 AI

不用 MCP 也能做完整課：

  1. 把 prompt-restock.txt 的全文貼給任何免費聊天 AI，請它回一份 n8n workflow JSON。
  2. 把回答存成 restock.json（只留 JSON，把前後的說明文字刪掉）。
  3. 在副本用 Import from File 匯入。
    你應該看到匯入成功、出現 4 個節點的流程（或接近 4 個；AI 做得不對，就是下一段要驗收的重點）。

後面的自己驗收完全一樣。

第 3 段：請 AI 做補貨提醒

把 prompt-restock.txt 的內容貼給 AI（做法 B 已經做過這步）。重點是它裡面寫了：只放 4 個節點、節點用中文名、不要通知／寄信／寫檔／HTTP Request、不用任何憑證、不要 Publish、做完說明每個節點在做什麼，還列了你接下來要測的四種情況。

  1. 貼上需求，讓 AI 在副本建立流程。
    你應該看到AI 回報建立成功。（實測整條路是：AI 用 MCP 送出流程程式 → 驗證「valid，4 個節點」→ 建立成功 → 執行。）

  2. 回到副本的 n8n 編輯器，打開 Overview 找到新流程，點進去。
    你應該看到4 個節點，名稱是中文，沒有通知、寄信、寫檔、HTTP Request；沒有被 Publish。

卡住了？流程多了不該有的節點（例如 Telegram）：這是 AI 沒照限制做。把限制再貼一次請它修，或自己刪掉；不要因為它「有功能」就留著。

卡住了？流程被 Publish 了：馬上到 Overview 把它 Unpublish，再重讀安全規則第 3 條。

  1. 按 Execute workflow（手動執行）。 你應該看到（N）：假庫存 1 筆；「低於門檻？」走 true；補貨草稿 1 筆，內容「衛生紙 剩 2，低於 3，記得補貨」。

對照答案：main-done.json，4 個節點。你的流程不用一字不差，但邏輯要一樣。

第 4 段：自己驗收

匯入或建立成功、有綠燈，都不算通過。 照順序做這四種情境，每次都記下 Executions 裡看到的筆數與草稿：

  1. N（正常）：衛生紙 2、門檻 3。
    你應該看到走 true，1 筆；草稿「衛生紙 剩 2，低於 3，記得補貨」。

  2. 剛好等於：把假庫存的 qty 改成 3（門檻也是 3）。
    你應該看到走 false，1 筆；沒有草稿。「低於」不含等於。想讓「剛好等於」也提醒，要把 If 改成「小於或等於」，這是改需求一次。

  3. M（缺資料）：把 qty 那一行整個拿掉。
    你應該看到不會報錯，走 false，沒有草稿。

  4. 打錯欄位：把 If 裡的 $json.qty 打成 $json.qyt。
    你應該看到也不會報錯，走 false，沒有草稿。

兩個「安靜地不提醒」要特別小心。 缺資料和打錯字都不會紅燈，只是沒通知；只看綠燈會以為一切正常。修法跟結業範例同一招：在 If 加一個「qty 存在（exists）」的條件，而且每種情境都要親自跑，不能相信 AI 說「我測過了」。

  1. 修一次錯：用第 4 點的錯誤，把 $json.qyt 改回 $json.qty，再跑 N。
    你應該看到回到走 true、1 筆、有草稿。

  2. 檢查沒有 Publish：到 Overview。
    你應該看到這條流程不是 Published 狀態（Published 標記位置見版本附頁）。

  3. 收尾：到 Instance-level MCP 關掉 Enable MCP access 或撤銷金鑰（Revoke access，位置待查證），再關掉副本的 PowerShell 視窗。
    你應該看到AI 用戶端再也連不上。

驗收

  • 正常 N。2／3 走 true，1 筆，草稿「衛生紙 剩 2，低於 3，記得補貨」。
  • 邊界。3／3 走 false，沒有草稿；說得出「低於」為什麼不含等於。
  • 缺資料。拿掉 qty，走 false，沒有草稿；說得出為什麼沒報錯卻是個風險。
  • 打錯欄位。$json.qyt 同樣走 false；改回 qty 後恢復。
  • 每個節點都說得出用途；能不看 AI 的說明，講清楚 If 在比什麼。
  • 改一次門檻（例如 min 改成 5），重跑 N，結果跟著變。
  • 沒被 Publish；MCP 已關掉或撤銷；副本裡沒有真憑證。
  • 變形題。加一個「qty 存在」的條件到 If，再跑缺資料，確認走 false 的原因是你設計的，不是意外；並想想要不要讓它通知你「資料缺」。（不附素材，自己改。）
卡關救援
  • 連不上 MCP（連線被拒或 404，實際訊息待查證）→ 看網址 → 填成了編輯器網址，漏了 /mcp-server/http，或埠不是 5688 → 改成 http://localhost:5688/mcp-server/http 再試 → 請 AI 列出工具確認。
  • 401 或沒有權限（實際訊息待查證）→ 看金鑰 → 金鑰貼錯、少了 Bearer ，或已經撤銷 → 重新取得金鑰、照格式 Authorization: Bearer <MCP 金鑰> → 重連確認。
  • AI 看不到我的流程 → 看流程有沒有開放給 MCP（官方說 MCP 預設只看得到有開放的流程，搜尋除外）→ 在副本裡把要用的流程開放（位置待查證）→ 再請 AI 搜尋一次。
  • 副本啟動說 5679 被占用 → 看有沒有設 N8N_RUNNERS_BROKER_PORT → 兩個埠都改成 5688、5689 → 重新啟動確認。
  • AI 給的 JSON 匯不進去 → 看是不是混進了說明文字或程式碼框的符號 → 只留 JSON 本體再存檔 → 重匯入確認有 4 個節點。
  • 流程被 AI Publish 了 → 到 Overview → 立刻 Unpublish → 確認狀態；之後再請 AI 重讀「不准 Publish」。
  • 打算用到真憑證 → 停 → 副本一律不放真憑證，這課的流程用不到。
