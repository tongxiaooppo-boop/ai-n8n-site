M9｜上線與維護

早報正式跑一週，備份還原後照常運作約 1 小時＋試跑一週先修：M6實測 n8n 2.48.4（2026-11-18）・你的畫面可能略有不同

成果與先修

早報正式跑一週，並做過一次「備份、隔離還原、確認能用」。 先完成 M6（錯誤流程要先上線）；早報和快照流程用 M5 做好的。已經會匯出匯入的人，可以直接從第 3 段「隔離還原」開始。 不用新帳號；主線沿用 M5 的 Telegram。費用 0 元，約 1 小時操作，加上一週觀察。

⚠️ 安全提醒：備份資料夾裡有憑證加上金鑰，等於整串鑰匙。不要放到公開或分享給別人的雲端資料夾，不要 commit 到 GitHub；放隨身碟或加密的地方（加密方法待查證，先記住原則）。不測 Webhook 的時候關掉 ngrok（M7）；n8n 要有登入密碼；匯出時不要用 --decrypted，它會把所有 token 和密碼用明文寫成檔案。

白話觀念

四件事，各一句話記住：

  1. 上線＝Publish 加上電腦要開著：自架的 n8n 跑在你的電腦上，電腦睡著或 n8n 關掉，排程就不會跑。
  2. 備份要三樣加一樣：流程、憑證、加密金鑰，加上 .n8n-files 的資料檔。少了金鑰，憑證就再也救不回來（流程還在，但每一把憑證都要重建）。
  3. 還原要隔離：先在另一個資料夾、另一個埠還原，確認能用才切換；不要直接蓋掉正式版。
  4. 升級前先備份、先在副本試：同一份測試檔，新舊版結果一樣才升級正式版。
正式版 →（匯出流程、憑證＋抄下金鑰＋複製 .n8n-files）→ 備份資料夾 →（帶金鑰匯入）→ 副本（另一個埠）→ 確認 → 才切換

素材包

  • ex1-done.json：家用記帳還原（3 節點）。
  • ex2-done.json：升級前後試跑（3 節點）。
  • data-ledger.csv：測試資料，記帳 2 筆。
  • data-upgrade-test.csv：升級測試檔，含開頭 0、空格子、引號裡的逗號。
  • week-log.csv：一週紀錄表，用 Excel 開。
  • 主線的早報流程用 M5 的 main-report-done.json，M9 不另做新流程。

兩個小練習的流程匯入後不需要憑證。兩份測試資料先放進 .n8n-files\m9\（Windows：C:\Users\<你>\.n8n-files\m9\，資料夾要自己建）。npx 版的路徑換法照 M5：把素材裡的 /home/node/.n8n-files/m9/… 改成 C:/Users/<你>/.n8n-files/m9/…。

主線：早報正式跑一週

分三段：先把早報全部上線，再備份，最後在另一個資料夾隔離還原。第 1 段之後要觀察一週。

第 1 段之後的一週

每天打開 week-log.csv 填一列：早報幾點到、每個來源的資料日期、有沒有 ⚠舊資料、有沒有收到錯誤通知、失敗的是哪個節點、有沒有補跑。補跑的做法：手動執行那一條收集流程，再手動跑早報。

你應該看到7 列都填了，失敗也照實寫，不是只寫成功的。週末、假日股價資料日不會變，不算失敗（M4、M5 學過）。

電腦睡眠或關機、終端機視窗關掉（M0 的 docker run -it --rm 關視窗就停）時，排程都不會跑。開回來之後會不會補跑錯過的那一次，待查證；Windows 睡眠設定的位置，待查證。

第 2 段：備份

備份要放四樣：流程、憑證（還是加密的）、加密金鑰、.n8n-files 的資料檔。n8n 開著也能匯出。

n8n 的資料放在哪：npx 版在 C:\Users\<你>\.n8n（環境變數 N8N_USER_FOLDER 可以改「家」的位置，n8n 會用它底下的 .n8n）；Docker 版在 volume n8n_data（容器裡的 /home/node/.n8n）。裡面有 database.sqlite（流程、憑證、執行紀錄）和 config（加密金鑰）。config 的內容長這樣：{"encryptionKey": "<一串英數字>"}。

  1. 建一個備份資料夾，日期用當天，例如 D:\n8n-backup\2026-01-05\。
    你應該看到資料夾建好了，是空的。

做法：npx

  1. 在 PowerShell 匯出流程與憑證（一個流程一個檔）：

    npx n8n export:workflow --backup --output=D:\n8n-backup\2026-01-05\workflows\
npx n8n export:credentials --backup --output=D:\n8n-backup\2026-01-05\credentials\

    你應該看到「Successfully exported N workflows.」和「Successfully exported N credentials.」（N 是你的數量）。匯出的憑證 "data" 是一串亂碼，因為還是加密的，要配原本的金鑰才有用。

  2. 打開 C:\Users\<你>\.n8n\config，把裡面的金鑰抄下來，存成另一個檔（例如 key.txt）放在同一個備份資料夾。
    你應該看到備份資料夾裡有 key.txt。這個檔和憑證放在一起就等於整串鑰匙，照上面的安全提醒處理。

  3. 複製整個 C:\Users\<你>\.n8n-files 到備份資料夾。
    你應該看到備份資料夾裡有 workflows、credentials 兩個資料夾，加上金鑰檔和 .n8n-files 的副本。

做法：Docker

Docker 版本機沒有實測，以下指令與輸出全部待查證。

  1. 用 docker exec 匯出，寫進掛載的 .n8n-files（M5），這樣 Windows 看得到：

    docker exec n8n n8n export:workflow --backup --output=/home/node/.n8n-files/backup/workflows/
docker exec n8n n8n export:credentials --backup --output=/home/node/.n8n-files/backup/credentials/

    你應該看到（待查證）成功訊息；Windows 的 .n8n-files\backup 底下有兩個資料夾。

  2. 用下面指令看金鑰，抄下來存成 key.txt：

    docker exec n8n cat /home/node/.n8n/config

    你應該看到（待查證）一段含 encryptionKey 的內容。

  3. 把 .n8n-files\backup 搬到備份資料夾，再複製整個 .n8n-files。
    你應該看到備份資料夾裡有 workflows、credentials、金鑰檔和 .n8n-files 的副本。

卡住了？不要用 --decrypted（會把所有 token、密碼用明文寫成檔案）。要照原本的做法匯出，憑證才是加密的。

第 3 段：隔離還原

在另一個資料夾、另一個埠還原。下面四種情境（N、M、D、E）都要做過一次。

做法：npx

  1. 開一個新的 PowerShell 視窗，設環境變數：

    $env:N8N_USER_FOLDER="C:\n8n-restore"
$env:N8N_ENCRYPTION_KEY="<備份裡的金鑰>"

    你應該看到沒有訊息。這個視窗之後的 n8n 都用 C:\n8n-restore 當家，並使用備份裡的金鑰。

  2. 匯入流程與憑證：

    npx n8n import:workflow --separate --input=D:\n8n-backup\2026-01-05\workflows\
npx n8n import:credentials --separate --input=D:\n8n-backup\2026-01-05\credentials\

    你應該看到匯入成功的訊息。匯入的流程一律變成「沒有 Publish」（import:workflow 會自動取消 Publish），所以副本不會自己跑排程。

  3. 換埠，讓副本和正式版可以同時開：

    $env:N8N_PORT="5688"
$env:N8N_RUNNERS_BROKER_PORT="5689"
npx n8n start

    你應該看到n8n 啟動。

卡住了？「n8n Task Broker's port 5679 is already in use. Do you have another instance of n8n running already?」：沒設 N8N_RUNNERS_BROKER_PORT，5679 被正式版占走了。兩個埠都改好，5678 和 5688 就能同時開。

  1. 打開 http://localhost:5688。第一次開會要求建立擁有者帳號（畫面待查證）。
    你應該看到流程和憑證都在。

做法：Docker

Docker 版本機沒有實測，以下全部待查證。

  1. 建新的 volume、用新的容器名稱，埠換成 5688，並帶入金鑰：

    docker volume create n8n_restore
docker run -it --rm --name n8n-restore -p 5688:5678 -e GENERIC_TIMEZONE=Asia/Taipei -e TZ=Asia/Taipei -e N8N_ENCRYPTION_KEY=<備份裡的金鑰> -v n8n_restore:/home/node/.n8n -v "D:\n8n-backup\<日期>:/backup:ro" docker.n8n.io/n8nio/n8n

    你應該看到（待查證）副本啟動。

  2. 另開一個終端機，用 docker exec 匯入備份（上一步的 -v ...:/backup:ro 把備份資料夾唯讀掛進容器的 /backup）：

    docker exec n8n-restore n8n import:workflow --separate --input=/backup/workflows/
docker exec n8n-restore n8n import:credentials --separate --input=/backup/credentials/

    你應該看到（待查證）匯入成功；打開 http://localhost:5688，流程和憑證都在。

四種情境

副本跟正式版讀的是同一個 .n8n-files（npx 版的允許區預設是作業系統家目錄底下的 .n8n-files，跟 n8n 資料放在哪無關）。所以在副本裡只准跑「讀」的流程，不要跑會寫快照、寫 Excel 的流程；要測通知，先把 Telegram 的 chat ID 換成測試用的對象。

  • N（正常）：帶金鑰匯入。 到副本手動跑小練習①（只讀檔）。
    你應該看到所有憑證都解得開；小練習①讀到 2 筆。

  • M（缺資料）：故意不設金鑰匯入。 另開一個新的 PowerShell 視窗（才不會沿用 N 設好的金鑰），用另一個資料夾，再匯入：

    $env:N8N_USER_FOLDER="C:\n8n-restore-nokey"
Remove-Item Env:N8N_ENCRYPTION_KEY -ErrorAction SilentlyContinue
npx n8n import:workflow --separate --input=<備份資料夾>\workflows\
npx n8n import:credentials --separate --input=<備份資料夾>\credentials\

    匯入都會顯示成功，但 n8n 會自己產生一把新的金鑰。照第 3 步換埠開起來，打開任何一個憑證，或手動跑一個用到憑證的流程（先把 Telegram 的 chat ID 換成測試對象，不要跑會寫檔的流程）。
    你應該看到用到憑證時失敗，訊息是「Credentials could not be decrypted. The likely reason is that a different "encryptionKey" was used to encrypt the data.」結論：這份備份不完整，不准切換。

  • D（重複）：複製整個 .n8n 資料夾還原。 照這個順序做，一步都不能跳：

    1. 先關掉正式版 n8n（資料庫還在寫入的時候，最新的變動可能在 -wal 檔裡，複製會不完整）。
    2. 把正式的 C:\Users\<你>\.n8n 整個資料夾複製成 C:\n8n-restore-copy\.n8n。
    3. 另開一個新的 PowerShell 視窗，先設副本的位置，再取消副本裡所有流程的 Publish：
    $env:N8N_USER_FOLDER="C:\n8n-restore-copy"
npx n8n unpublish:workflow --all

    ⚠️ 執行前再看一次：這個視窗一定要先設好 N8N_USER_FOLDER。沒設的話，指令會作用在正式版，把正式版的流程全部取消 Publish。

    1. 照第 3 步換埠，才開副本；正式版可以重新打開。

    你應該看到「All workflows unpublished successfully」，之後副本裡 Publish 的流程是 0 個。原因：整包複製的副本，原本 Publish 的流程還是 Publish；沒先取消的話，副本一開，正式版和副本的排程會同時跑，Telegram 收到兩份早報。如果真的收到兩份：馬上關掉副本，到副本把流程取消 Publish。

  • E（故障）：用壞掉的資料庫開不起來。 資料庫檔壞掉時，n8n 會重試 5 次。
    你應該看到「SQLITE_CORRUPT: database disk image is malformed」，最後「There was an error initializing DB」，開不起來。處理：停止切換、正式版照常跑，不要拿壞的備份覆蓋正式資料，改用前一份備份再試。

確認副本能用之後，再決定要不要切換；這門課的練習做到「確認能用」就結束，關掉副本即可。

卡住了？匯入後流程都沒在跑：正常，匯入會取消 Publish，確認後再自己 Publish。

小練習①：家用記帳還原

練習備份與還原的完整動作：記帳檔「不見」後，從備份複製回來，再讀一次。

節點 用途 關鍵設定
手動執行（Manual Trigger） 手動啟動 不用設定
讀還原的記帳檔（Read/Write Files from Disk） 讀還原回來的記帳檔 Read，路徑 /home/node/.n8n-files/m9/data-ledger.csv（npx 換路徑，見素材包）
解開CSV（Extract from File） CSV 變回一筆一筆的資料 格式 CSV，打開 Exclude Byte Order Mark (BOM)

  1. 把 data-ledger.csv 放到 .n8n-files\m9\，再複製一份到備份資料夾。
    你應該看到兩個位置都有這個檔。

  2. 刪掉 .n8n-files\m9\ 裡的原檔（假裝不見了），再從備份複製回來。
    你應該看到.n8n-files\m9\data-ledger.csv 又出現了。

  3. 匯入 ex1-done.json，按 Execute workflow。位置見版本附頁。
    你應該看到「解開CSV」2 筆，第一筆 item: 早餐、amount: "65"（字串，不是數字 65）；第一筆沒有 note 欄位（空格子讀回來是「沒有這個欄位」）。要比對列數與欄位，不是只看有沒有綠燈。

卡住了？「Access to the file is not allowed.」：路徑不在 .n8n-files 裡，或 npx 版沒有換掉素材裡的 Docker 路徑（M5）。

小練習②：升級前後試跑

升級前，用同一份測試檔在正式版和新版副本各跑一次，比對結果一樣才升級正式版。

節點 用途 關鍵設定
手動執行（Manual Trigger） 手動啟動 不用設定
讀測試檔（Read/Write Files from Disk） 讀升級測試檔 Read，路徑 /home/node/.n8n-files/m9/data-upgrade-test.csv（npx 換路徑，見素材包）
解開CSV（Extract from File） CSV 變回一筆一筆的資料 格式 CSV，打開 Exclude Byte Order Mark (BOM)

  1. 把 data-upgrade-test.csv 放到 .n8n-files\m9\，匯入 ex2-done.json，在正式版跑一次，把結果記下來（或從 Executions 複製）。
    你應該看到「解開CSV」2 筆；code 是 "0050"（開頭的 0 還在）；第一筆 note 是 盤後,不是即時；第二筆 price 是 "100"，沒有 note。

  2. 先備份（第 2 段）。回到第 3 段開副本的那個 PowerShell 視窗（環境變數還在），先按 Ctrl+C 停掉舊版副本，確認它停了，再用新版開副本：npx n8n@<新版本> start。正式版不要停，也不要在正式版的視窗做這一步。版本號查 n8n 官方 Changelog。Docker 版：docker pull docker.n8n.io/n8nio/n8n:<版本>，再用同一個 volume 重新 docker run（官方 Update n8n 頁；Docker 實際效果待查證）。
    你應該看到新版 n8n 在副本的埠開起來，流程和憑證都在。

  3. 在副本匯入同一個 ex2-done.json，再跑一次，和第 1 步的結果比對。
    你應該看到兩邊都是 2 筆，code 都是 "0050"，note 與 price 都一樣。一樣才升級正式版；不一樣就先不升，查 Changelog。

卡住了？新版開不起來：換回舊版本號，並用升級前的備份還原，不要只換版本號。大版本升級可能會改資料庫結構，改了就回不去，所以「先備份」是規則，不是建議。

看懂執行紀錄

打開 Executions，一週裡每天看：

  • 每條收集流程一天一筆、早報一天一筆。
  • 有失敗的話，點開看是哪個節點失敗。
  • 錯誤流程有沒有跟著跑（M6）。
  • 有排程卻沒有那一天的紀錄，代表那時 n8n 沒開或電腦睡著，不是流程壞了。
  • 副本裡的 Executions 跟正式版分開，在副本跑的不會出現在正式版。

不能只看有沒有綠燈：還要看每個來源的資料日期、有沒有 ⚠舊資料、列數與欄位對不對。

驗收

  • 正常 N。week-log.csv 一週 7 列如實寫（含失敗與補跑）；帶金鑰在副本還原，小練習①讀到 2 筆。
  • 缺資料 M。不帶金鑰還原，看到「Credentials could not be decrypted」，並決定不切換。
  • 重複 D。說得出整包複製還原為什麼要先取消 Publish；副本裡 Publish 的流程是 0 個。
  • 故障 E。壞掉的備份開不起來時，正式版沒被動到，改用前一份備份。
  • 升級。小練習②在新舊版結果一樣，才升級正式版。
  • 變形題。備份放另一個地方、訂好兩個數字並計時，備註寫進 week-log.csv。
卡關救援
  • 「Credentials could not be decrypted」→ 看副本的 config 金鑰是不是備份裡的那一把 → 金鑰不對，或沒設 N8N_ENCRYPTION_KEY → 用備份裡的金鑰重來，在新資料夾重新匯入，確認用到憑證的節點不再報錯。
  • 「n8n Task Broker's port 5679 is already in use」→ 看有沒有另一個 n8n 開著 → 副本沒設 N8N_RUNNERS_BROKER_PORT → 設成 5689 並一併設 N8N_PORT，確認 5678 和 5688 都能開。
  • 同一天收到兩份早報 → 看副本裡有沒有 Publish 的流程 → 副本的排程還開著 → 關掉副本，到副本把流程取消 Publish，或先跑 unpublish:workflow --all；確認隔天只收到一份。
  • 「SQLITE_CORRUPT: database disk image is malformed」→ 看備份的資料庫檔 → 備份壞了 → 停止切換，換前一份備份，確認副本能開。
  • 早報沒來、Executions 也沒有紀錄 → 看電腦當時有沒有睡著、n8n 有沒有在跑 → 不是流程壞了 → 讓電腦保持開機、n8n 持續執行，再確認隔天有紀錄。
  • 「Access to the file is not allowed.」→ 看讀檔路徑 → 路徑不在 .n8n-files（M5） → 把檔案放進去、改路徑，重跑確認。
  • 匯入後流程都沒在跑 → 看流程是不是已 Publish → 正常，匯入會取消 Publish → 確認副本沒問題後再自己 Publish。
  • 升級後開不起來 → 看新版的錯誤訊息 → 版本或資料庫結構不相容 → 換回舊版本號，用升級前的備份還原（不要只換版本號），確認能開。

求助時附 n8n 版本、哪個節點、錯誤訊息原文、已經試過什麼。截圖和貼文字前，先遮住金鑰（config 的內容也算）和個資。
