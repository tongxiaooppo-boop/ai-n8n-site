M6｜錯誤處理與可靠性

來源壞掉時收到提醒，不會傳出空白早報約 2 小時先修：M5實測 n8n 2.48.4（2026-11-18）・你的畫面可能略有不同

成果與先修

來源壞掉時，n8n 會自己再試幾次；真的失敗，手機收到一則「⚠️ 流程失敗」，而不是安靜地送出空的或舊的早報。 先完成 M5。已經會設定 Publish 與 Telegram 憑證的人，可以直接從主線第 2 段開始。 不用新帳號，沿用 M5 的 Telegram Bot。費用 0 元，時間約 90–120 分鐘。股價與匯率只供紀錄與提醒。

白話觀念

四件事，各一句話記住：

  1. 逾時（Timeout）：等太久就放棄，免得流程卡住。逾時的錯誤訊息是「The connection was aborted, perhaps the server is offline」，不是「timeout」。
  2. 重試（Retry）：Max Tries 3＝總共呼叫 3 次，不是失敗後再試 3 次。只對「暫時壞」有用（503、逾時）；401（鑰匙錯）、404（網址錯）重試幾次都一樣，不該重試。
  3. 錯誤流程（Error Workflow）：一條獨立的小流程，用 Error Trigger 開頭；在別條流程的 Workflow Settings 指定它，那條流程失敗時就會跑它。只有已 Publish、由排程或 Webhook 正式觸發的執行失敗才會觸發；手動按執行失敗不會（實測）。
  4. 壞掉不冒充正常：資料錯誤要變成「真正的失敗」（Stop And Error），才會留下紅色紀錄並觸發錯誤流程；不要用 0 或空字串假裝成功。
抓資料（Timeout 10 秒 → 失敗就重試，最多 3 次）→ 還是失敗 → 這條流程失敗
                                                          ↓
                    錯誤觸發 → 整理錯誤 → 傳到Telegram（另一條流程，手機收到提醒）

素材包

  • main-fx-done.json：「匯」收集流程加上逾時與重試（只含關鍵 4 節點）。
  • main-errwf-done.json：錯誤流程（3 節點：錯誤觸發 → 整理錯誤 → 傳到Telegram）。
  • ex1-done.json：植物提醒來源故障（每分鐘排程，模擬來源回 503）。
  • ex2-done.json：支出缺金額，正常版。
  • ex2-missing-done.json：支出缺金額，缺金額版。

用 Import from File 匯入，位置見版本附頁。錯誤流程匯入後要自己選 Telegram 憑證、填 chat ID。小練習①用的是 M4 的模擬來源，要先 Publish（M4 已做過；沒做就匯入 mock-source.json 並發布）。

主線：來源壞掉時收到提醒

先替收集流程加逾時與重試，再建一條錯誤流程，並接到四條收集流程上。

第 1 段：替 M5 的收集流程加逾時與重試

在你自己的 M5「匯」流程上改這兩處，M5 的「存快照」節點保留；main-fx-done.json 只當對照（它只含前 4 個關鍵節點）。

節點 用途 關鍵設定
排程（Schedule Trigger） 每天啟動 每天 7 點，不變
抓匯率（HTTP Request） 取得央行歷史資料 Options 加 Timeout 10000（毫秒，＝10 秒）；節點 Settings 開 Retry On Fail、Max Tries 3、Wait Between Tries 2000（毫秒）
最新一筆（Limit） 取最後一筆 不變
整理（Edit Fields (Set)） 整理成快照欄位 不變

  1. 打開「抓匯率」，在 Options 加 Timeout，填 10000。位置見版本附頁。
    你應該看到Options 裡多了一項 Timeout，值是 10000。

  2. 在同一個節點的 Settings 打開 Retry On Fail，Max Tries 填 3，Wait Between Tries 填 2000。
    你應該看到三個欄位都有值；Max Tries 是 3，意思是失敗時總共最多呼叫 3 次。

  3. 執行整條流程一次，確認照常。
    你應該看到整理 1 筆，status 是 ok，和 M5 一樣；沒有紅色節點。

卡住了？找不到 Retry On Fail：它在節點的 Settings 分頁，不是 Parameters；找不到 Timeout：它在 Options 的新增選項裡。位置見版本附頁。

股、警、聞三條也照同樣的兩處設定改（Timeout 10000、Retry On Fail、Max Tries 3、Wait Between Tries 2000），不重複步驟。

第 2 段：建錯誤流程並接上

建一條獨立的流程，專門在別條流程失敗時傳訊息到手機。

節點 用途 關鍵設定
錯誤觸發（Error Trigger） 別條流程失敗時啟動 不用設定
整理錯誤（Edit Fields (Set)） 組成一段通知文字 欄位 text，String，Expression 如下
傳到Telegram（Telegram） 傳到手機 選憑證、填 chat ID，文字 {{ $json.text }}，Append n8n Attribution 關掉

text 的 Expression（照抄素材）：

⚠️ 流程失敗：{{ $json.workflow.name }}
節點：{{ $json.execution.lastNodeExecuted }}
訊息：{{ $json.execution.error.message }}
時間：{{ $now.toFormat('MM-dd HH:mm') }}

四行分別是：哪條流程、哪個節點、錯誤訊息原文、什麼時間。$json.workflow、$json.execution 是 Error Trigger 交出來的資料，不用自己準備。

  1. 匯入 main-errwf-done.json，在「傳到Telegram」選你的 Telegram 憑證、填 chat ID，確認 Append n8n Attribution 是關的。位置見版本附頁。
    你應該看到3 個節點依序連線，傳到Telegram 沒有紅色警示。

  2. 錯誤流程本身要不要 Publish：如果介面要求才 Publish（待查證）。
    你應該看到流程列表裡有「M6 錯誤流程」。

  3. 到股、匯、警、聞四條流程，各自打開 Workflow Settings，把 Error Workflow 選成「M6 錯誤流程」。位置見版本附頁。
    你應該看到四條流程的 Error Workflow 都顯示「M6 錯誤流程」。

卡住了？Error Workflow 清單裡找不到「M6 錯誤流程」：先確認錯誤流程開頭是 Error Trigger，並且已存檔。

  1. 測試：不能用手動執行測，手動執行失敗不會觸發錯誤流程。改用下面的小練習①：它是每分鐘的排程，Publish 後屬於正式觸發。
    你應該看到手機收到「⚠️ 流程失敗：…／節點：…／訊息：…／時間：…」四行；Executions 裡錯誤流程有自己的一筆紀錄。Telegram 實際畫面（待查證）。

小練習①：植物提醒來源故障

每分鐘到模擬來源要「澆水資料」，來源故意回 503；重試用完仍失敗，錯誤流程就傳通知到手機。

節點 用途 關鍵設定
排程（Schedule Trigger） 每分鐘啟動 每 1 分鐘
抓澆水資料（HTTP Request） 呼叫模擬來源 網址 http://localhost:5678/webhook/mock?status=503&t=plant；逾時與重試同主線（Timeout 10000、Max Tries 3、Wait 2000）
提醒內容（Edit Fields (Set)） 準備提醒文字 text＝今天記得澆水，String

  1. 匯入 ex1-done.json，打開 Workflow Settings，Error Workflow 選「M6 錯誤流程」。
    你應該看到3 個節點依序連線；Error Workflow 顯示「M6 錯誤流程」。

  2. 按 Publish，等 1–2 分鐘。模擬來源也要是已 Publish 的狀態。
    你應該看到Executions 出現失敗紀錄，「抓澆水資料」是紅色的，訊息「Service unavailable - try again later…」；手機收到錯誤通知。

卡住了？訊息是「The connection was aborted, perhaps the server is offline」，多半是模擬來源沒 Publish，回去發布再等一分鐘。

  1. 測完一定要 Unpublish，不然每分鐘會發一則通知到手機。
    你應該看到流程列表上它不再顯示已發布；之後 Executions 不再新增紀錄。

變形題：只把網址裡的 status=503 改成 status=401（其他參數保留，完整網址是 http://localhost:5678/webhook/mock?status=401&t=plant），比較重試的差別。401 是鑰匙錯，重試 3 次都一樣失敗；這種節點應該關掉 Retry On Fail，直接通知。（不附素材，自己改網址。）

小練習②：支出缺金額

一筆支出若沒有金額，要變成真正的失敗，而不是記成 0 元。

節點 用途 關鍵設定
手動（Manual Trigger） 手動啟動 無
一筆支出（Edit Fields (Set)） 準備測資 item＝午餐（String）、amount＝120（Number）
有金額嗎（If） 檢查金額是否存在 條件：{{ $json.amount }} 的 exists（Number）
記帳（Edit Fields (Set)） true 分支，組成記帳文字 text＝{{ $json.item + ' ' + $json.amount + ' 元' }}
停下報錯（Stop And Error） false 分支，讓整次執行失敗 錯誤訊息 支出缺金額：{{ $json.item }}

  1. 匯入正常版 ex2-done.json，執行。
    你應該看到「有金額嗎」的 true 分支 1 筆，「記帳」輸出 午餐 120 元。

  2. 匯入缺金額版 ex2-missing-done.json（「一筆支出」沒有 amount），執行。
    你應該看到「有金額嗎」的 false 分支 1 筆，「停下報錯」變紅，訊息「支出缺金額：午餐」，整次執行算失敗，「記帳」沒有跑。

卡住了？缺金額版記成「午餐 undefined 元」或 0 元：檢查「有金額嗎」的 true、false 是不是接反，缺金額那一筆應走 false 分支。

  1. 想一想：如果這條是排程正式觸發，這個失敗會觸發錯誤流程；手動按的不會。
    你應該看到手動執行時只有這次執行是紅的，手機沒有通知。

看懂執行紀錄

打開 Executions。重試的那幾次不會各自一筆紀錄，整次執行只有一筆；節點裡是否看得到嘗試次數（待查證）。 錯誤流程是另一筆獨立紀錄：失敗的流程一筆、「M6 錯誤流程」一筆，要兩筆一起看。 Stop And Error 的節點是紅色，後面不會再跑；先看哪個節點紅、訊息是什麼，再看前一個節點輸出了幾筆。 不能只看有沒有綠燈：錯誤通知有沒有送到手機，要和紀錄一起確認。

驗收

  • 正常 N。主線「匯」照常執行，整理 1 筆、status 是 ok。
  • 缺資料 M。匯入 ex2-missing-done.json 執行：缺金額版失敗，訊息是「支出缺金額：午餐」，不是記成 0 元。
  • 重跑 D。小練習①在 Publish 期間，每分鐘一筆失敗紀錄與一則通知；Unpublish 後停止。錯誤通知不保證只送一次，補跑前先看手機與 Executions。
  • 故障 E。確認小練習①已選錯誤流程、Publish 後等 1–2 分鐘：503 重試後失敗，Executions 有失敗紀錄，手機收到錯誤通知。
  • 變形題。把小練習①網址的 status=503 改成 status=401（其他參數保留），說明為什麼這個節點應該關掉重試；測完 Unpublish。
卡關救援
  • 手動執行失敗卻沒收到通知 → 看流程是怎麼觸發的 → 手動執行不會觸發錯誤流程，改用已 Publish 的排程 → 等排程跑過，確認 Executions 出現錯誤流程那一筆。
  • 錯誤流程完全沒跑 → 看失敗流程的 Workflow Settings → Error Workflow 沒選「M6 錯誤流程」，選好 → 再讓它失敗一次確認。
  • 手機每分鐘一直響 → 看小練習①是不是還在發布 → 忘了 Unpublish，馬上取消發布 → 確認 Executions 不再新增。
  • 「The connection was aborted, perhaps the server is offline」→ 看是不是逾時，或模擬來源沒 Publish → 發布模擬來源、等幾秒再跑 → 確認訊息改變。
  • 「Service unavailable - try again later…」→ 看網址是不是 ?status=503 → 來源回 503、重試用完才失敗，這是預期結果 → 想要正常就只把 status=503 改成 status=200，其他參數保留。
  • 401 一直重試 → 看 Retry On Fail 是不是還開著 → 401 重試也一樣失敗，關掉重試、直接通知 → 確認只呼叫一次就失敗。
  • 錯誤通知也沒來 → 去 Executions 看錯誤流程那一筆 → 可能是 Telegram 憑證或通知管道本身壞了，修好憑證與 chat ID → 手機收到測試訊息。不要宣稱告警一定送達。

求助時附 n8n 版本、哪個節點、錯誤訊息原文、已經試過什麼。截圖和貼文字前，先遮住 Bot token、chat ID 和個資。
