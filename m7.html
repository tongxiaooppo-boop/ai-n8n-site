M7｜Webhook 與子流程

在 Telegram 傳「查 2330」就回覆收盤價約 3 小時先修：M6實測 n8n 2.48.4（2026-11-18）・你的畫面可能略有不同

成果與先修

在 Telegram 傳「查 2330」，就回覆這檔股票最近交易日的收盤價（盤後資料，不是即時報價）。 先完成 M6（要會 Publish、設定憑證、用 Executions 看紀錄）。已經做過 M5 子流程的人，可以直接從主線第 1 段開始。 主線第 1、2 段不用新帳號；第 3 段（Telegram）是進階（入口 4 個＋子流程 4 個，共 8 個節點），要沿用 M5 的 Telegram Bot，並註冊 ngrok 免費帳號。做不到第 3 段，第 1、2 段做完也算完成本模組的主線。 費用 0 元（ngrok 免費版要不要綁卡，待查證），時間約 3 小時。股價只供紀錄與提醒，不是投資建議。

白話觀念

四件事，各一句話記住：

  1. Webhook＝流程的門鈴：別的程式（或你自己用 curl.exe）按一下網址，流程就開始跑，還能把結果回給按門鈴的人（用 Respond to Webhook 回覆）。
  2. 測試網址和正式網址：測試網址 http://localhost:5678/webhook-test/<路徑>，只在節點按下聽取測試時才有效，資料會直接顯示在畫布上；正式網址 http://localhost:5678/webhook/<路徑>，要 Publish 後才有效，結果不會顯示在畫布，要到 Executions 看。最常見的卡關，就是拿測試網址當正式用。
  3. 門口要有鎖：網址可能被別人知道，所以要檢查標頭密語；錯的直接 403，流程連跑都不跑。流程裡也只接受固定格式的指令（「查＋數字」），其他一律拒絕，不要「猜」對方想做什麼。
  4. 子流程的輸入：M5 的快照子流程是「整包收下」（Accept all data）；這次的查價子流程只收一個欄位 code。把輸入寫清楚，呼叫的人就知道要給什麼，同一個子流程可以讓 HTTP 入口和 Telegram 入口重用。
curl.exe 或 Telegram → 入口（驗密語、檢查指令）→ 呼叫查價子流程（只收 code）→ 回覆

素材包

  • sub-quote-done.json：查價子流程（4 節點）。
  • main-http-done.json：HTTP 入口（5 節點）。
  • main-telegram-done.json：Telegram 入口（4 節點，進階）。
  • ex1-done.json：家庭提醒入口（5 節點）。
  • ex2-done.json：手機查採買清單（3 節點）。
  • req-2330.json：請求檔，查 2330。
  • req-9999.json：請求檔，查 9999（找不到的情境）。
  • req-empty.json：請求檔，空的（格式錯的情境）。
  • req-family-ok.json：請求檔，家庭提醒，欄位齊全。
  • req-family-missing.json：請求檔，家庭提醒，少了 when。

用 Import from File 匯入，位置見版本附頁。匯入後要自己補的事：

  • 查價子流程要先匯入並 Publish。
  • 兩個入口的「呼叫查價」匯入後要自己選子流程。
  • 三個 Webhook 節點（HTTP 入口、兩個小練習）要自己選標頭驗證憑證，三個共用同一把。
  • main-telegram-done.json 要自己選 Telegram 憑證，並把「你的chatID」換成自己的。

把請求檔下載到同一個資料夾，之後在 PowerShell 先 cd 到那個資料夾再送請求。

主線：傳「查 2330」回覆收盤價

分三段：先做查價子流程，再做 HTTP 入口在自己電腦測，最後（進階）接上 Telegram。

第 1 段：查價子流程

這條流程自己不會啟動，要等別的流程呼叫它才會跑。

節點 用途 關鍵設定
子流程入口（Execute Workflow Trigger） 子流程的入口，規定要收什麼 輸入方式選「定義輸入欄位」，加一個 code（字串）
抓全部股價（HTTP Request） 取得全部上市股票的最近交易日資料 網址照素材；沿用 M6 的逾時與重試（Timeout 10000、Retry On Fail、Max Tries 3、Wait Between Tries 2000）
挑這檔（Filter） 只留下 code 那一檔 條件比對代號；節點 Settings 開 Always Output Data
回覆內容（Edit Fields (Set)） 組出要回覆的文字 欄位 code、found（Boolean）、text（String）

「挑這檔」開了 Always Output Data，所以代號不存在時，也會有一筆空資料往下走，「回覆內容」才有機會寫「找不到」，而不是整條流程安靜地沒有輸出。

text 有三種結果（照素材的 Expression，不用自己寫）：

  • 有成交：台積電（2330）YYYY-MM-DD 收盤 NNN 元（盤後資料，不是即時價）。民國年會自動換成西元年。
  • 沒有成交：收盤價是空的，就回 名稱（代號）YYYY-MM-DD 沒有成交。
  • 找不到：回 找不到 9999（只查得到上市股票），不會回 0 元。

  1. 匯入 sub-quote-done.json，打開「子流程入口」，確認輸入方式是定義輸入欄位、有一個 code（字串）。位置見版本附頁。
    你應該看到4 個節點依序連線；子流程入口只有一個欄位 code。

  2. 按 Publish。
    你應該看到流程列表上它是已發布狀態。先不測，下一段由入口流程呼叫它時一起測（子流程要被呼叫才會跑）。

卡住了？之後呼叫時出現「Workflow is not active」，就是這條子流程沒 Publish。

第 2 段：HTTP 入口，在自己電腦測

節點 用途 關鍵設定
收到查詢（Webhook） 流程的門鈴，收 POST 請求 HTTP Method POST、Path m7-quote、Authentication 選 Header Auth、Respond 選 Using 'Respond to Webhook' Node
指令對嗎（If） 檢查指令是不是「查＋數字」 條件：指令符合「查」加 4–6 位數字（照素材 Expression）；true、false 兩條路
呼叫查價（Execute Sub-workflow） true 分支，呼叫查價子流程 選「M7 查價子流程」；Workflow Inputs 的 code 是指令裡的數字
回覆價格（Respond to Webhook） 把結果回給按門鈴的人 Respond With 選 JSON；內容 ok 是 true、text 是子流程給的文字
回覆格式錯（Respond to Webhook） false 分支，拒絕不合格式的指令 Respond With 選 JSON；Response Code 400；內容是「請傳「查 代號」，例如：查 2330」

  1. 建標頭驗證憑證：Credentials 新增 Header Auth，Name 填 X-Family-Key，Value 填你自己想的密語。位置見版本附頁。
    你應該看到憑證存好了。素材驗證用的密語是 DEMO_ONLY，你自己的不要用這個。

  2. 匯入 main-http-done.json，「收到查詢」選剛建的憑證，「呼叫查價」選「M7 查價子流程」。
    你應該看到5 個節點連線完整；兩個選項都沒有紅色警示。

卡住了？「呼叫查價」的子流程清單是空的或找不到：確認第 1 段的子流程已 Publish，並重新整理頁面。

  1. 先用測試網址：在「收到查詢」打開 Test URL，按聽取測試（按鈕名稱見版本附頁，待查證）。PowerShell 先 cd 到素材資料夾，再送： curl.exe -s -X POST http://localhost:5678/webhook-test/m7-quote -H "X-Family-Key: 你的密語" -H "Content-Type: application/json" --data-binary "@req-2330.json"
    你應該看到畫布上資料一路流過去，「指令對嗎」走 true；PowerShell 印出 {"ok":true,"text":"台積電（2330）YYYY-MM-DD 收盤 NNN 元（盤後資料，不是即時價）"}。

卡住了？一定打 curl.exe，不是 curl：PowerShell 5.1 的 curl 是別的指令，會跳一堆紅字。也不要用 -d '{"command":"查 2330"}'，PowerShell 5.1 會吃掉引號，n8n 回 422「Failed to parse request body」；一律用請求檔。

  1. 按 Publish，改用正式網址（網址裡的 webhook-test 改成 webhook），照順序送：

    • N：req-2330.json。
    • D：同一個請求再送一次。
    • M：req-empty.json。
    • E：把密語改成錯的，送 req-2330.json。
    • 找不到：req-9999.json。

    你應該看到

    • N：200，{"ok":true,"text":"台積電（2330）YYYY-MM-DD 收盤 NNN 元（盤後資料，不是即時價）"}。
    • D：回一模一樣的內容（只是查詢，送兩次沒有副作用）。
    • M：400，{"ok":false,"text":"請傳「查 代號」，例如：查 2330"}。
    • E：403，內文 Authorization data is wrong!。
    • 找不到：200，找不到 9999（只查得到上市股票），不是 0 元。

卡住了？404「The requested webhook "POST m7-quote" is not registered」：用了正式網址卻還沒 Publish，或剛 Publish 還沒生效，等幾秒再試。

第 3 段：Telegram 入口（進階）

做完這段，手機就能直接傳「查 2330」。這段要比前面多一些準備，做不到也不影響主線完成。

為什麼要通道：Telegram 要能從網路連到你電腦的 n8n，而且一定要 HTTPS，localhost 它連不到。用 ngrok 免費版當通道（要註冊；要不要綁卡待查證）。備案是 Cloudflare Quick Tunnel：免帳號，但每次網址都會變，變了就要重設。

節點 用途 關鍵設定
Telegram觸發（Telegram Trigger） 收到 Bot 的新訊息就啟動 憑證選你的 Telegram Bot；Updates 選 message
本人且指令對（Filter） 只放行本人、而且是「查＋數字」的訊息 條件：chat ID 等於你的，且文字符合格式；把「你的chatID」換成自己的
呼叫查價（Execute Sub-workflow） 呼叫同一個查價子流程 選「M7 查價子流程」；code 是文字裡的數字
回覆Telegram（Telegram） 把結果傳回去 憑證同上；chat ID 取自觸發的那則訊息；Append n8n Attribution 關掉

一個 Bot 同時只能接一個 Telegram 觸發（節點說明寫的）；M5 的早報用同一個 Bot 傳送沒關係。

⚠️ 安全提醒：ngrok 會把整個 n8n（包含編輯器）開到網路上。應該只放行 /webhook/ 開頭的路徑；ngrok 的設定方式（待查證）。在那之前：n8n 一定要有登入密碼，不測的時候關掉 ngrok。「本人且指令對」確保只有你本人、而且只有「查＋數字」會被處理，別人傳的訊息直接丟掉。

開 ngrok 之前先確認：打開 http://localhost:5678 要輸入帳號密碼才進得去。如果不用登入就能進編輯器，先停下來，不要開 ngrok。路徑限制查證前，通道只在測試時短時間開著，網址不要給別人，測完就關。

  1. 安裝 ngrok 並註冊帳號，執行 ngrok http 5678，取得一個 https://… 網址。ngrok 的實際畫面與指令輸出（待查證）。
    你應該看到終端機出現一個對外的 HTTPS 網址（以下寫成 https://你的網址/）。

  2. 先停掉正在跑的 n8n，再加上 WEBHOOK_URL 用原本的方式重開（ngrok 那個視窗不要關）：

    • Docker：先停掉舊的容器，再用你 M0 的 docker run 指令加上 -e WEBHOOK_URL=https://你的網址/；埠號、資料夾掛載等其他參數照舊，不要另開一個同埠的容器。
    • npx：在跑 n8n 的視窗按 Ctrl+C 停掉，先 $env:WEBHOOK_URL="https://你的網址/"，再 npx n8n。

    實際效果（待查證）。
    你應該看到n8n 重開後可以正常登入。

  3. 匯入 main-telegram-done.json，選 Telegram 憑證和「M7 查價子流程」，按 Publish。

卡住了？傳了話但 Executions 完全沒有紀錄：ngrok 網址變了、WEBHOOK_URL 沒設或設了沒重開 n8n，或同一個 Bot 有兩個 Telegram 觸發。

  1. 在 Telegram 傳「查 2330」。

小練習①：家庭提醒入口

收到 title 和 when 兩個欄位才整理成一筆提醒草稿，欄位不齊就回 400 拒絕。

節點 用途 關鍵設定
收到提醒（Webhook） 收 POST 請求 Path m7-family、Authentication 選 Header Auth（同一把憑證）、Respond 選 Using 'Respond to Webhook' Node
欄位齊嗎（If） 檢查 title 和 when 都有 true、false 兩條路
整理草稿（Edit Fields (Set)） true 分支，組出草稿 欄位 title、when，加 status 固定寫 draft
回覆成功（Respond to Webhook） 回草稿給對方 Respond With 選 JSON
回覆缺欄位（Respond to Webhook） false 分支，拒絕 Response Code 400；內容是「要有 title（提醒什麼）和 when（什麼時候）」

  1. 匯入 ex1-done.json，「收到提醒」選標頭驗證憑證，按 Publish。
    你應該看到5 個節點連線完整；流程是已發布狀態。

  2. 在 PowerShell 送 req-family-ok.json 到 http://localhost:5678/webhook/m7-family（寫法同主線，網址換掉）。
    你應該看到200，{"ok":true,"draft":{"title":"倒垃圾","when":"週二 19:30","status":"draft"}}。status 是 draft：只是草稿，還沒有真的排進任何行事曆。

  3. 送 req-family-missing.json，再把密語改錯送一次。
    你應該看到缺欄位回 400，要有 title（提醒什麼）和 when（什麼時候）；密語錯回 403。

卡住了？404「…is not registered」：沒 Publish，或路徑不是 m7-family。

小練習②：手機查採買清單

一個用 GET 的門鈴：按一下就回一份假的採買清單。

節點 用途 關鍵設定
查清單（Webhook） 收 GET 請求 HTTP Method GET、Path m7-shopping、Authentication 選 Header Auth、Respond 選 Using 'Respond to Webhook' Node
採買清單（Edit Fields (Set)） 準備假清單 items（Array）、text（String）
回覆清單（Respond to Webhook） 回給對方 Respond With 選 JSON；內容有 ok、count、text

  1. 匯入 ex2-done.json，選標頭驗證憑證，按 Publish。
    你應該看到3 個節點連線完整；流程是已發布狀態。

  2. 在電腦的 PowerShell 測（GET 不用請求檔）： curl.exe -s http://localhost:5678/webhook/m7-shopping -H "X-Family-Key: 你的密語"
    你應該看到200，{"ok":true,"count":3,"text":"牛奶、雞蛋、衛生紙"}。

  3. 不帶密語再送一次。
    你應該看到403，Authorization data is wrong!。

手機要用得到，需要第 3 段的通道；而且手機瀏覽器不能自己加標頭，要用能設定標頭的 App（例如 iPhone 的捷徑，待查證）。

變形題：在主線「指令對嗎」再加一個條件，只允許你的自選股（例如 2330、2317、0050），其他代號回「這檔不在你的清單」。重點：不在清單就說不在清單，不要回 0 元或空白。（不附素材，自己改。）

看懂執行紀錄

打開 Executions，注意四件事：

  • 正式網址的執行，只在 Executions 看得到，不會顯示在畫布上。
  • 子流程是另一筆紀錄：每呼叫一次，就多一筆子流程自己的紀錄，要和入口那一筆一起看。
  • 403 被擋的請求沒有紀錄：流程根本沒跑。要知道有沒有人亂試，不能靠 Executions。
  • 400 格式錯算成功的一筆：流程跑完了，只是回了拒絕。打開那一筆，看資料是走 false 那條（「回覆格式錯」）。

不能只看有沒有綠燈：還要看資料走了哪一條、子流程有沒有被呼叫、回覆的狀態碼對不對。

驗收

  • 正常 N。用正式網址送 req-2330.json，回最近交易日收盤價，文字寫明是盤後資料。
  • 缺資料 M。送 req-empty.json，回 400，要求照「查 代號」的格式。
  • 重跑 D。同一個請求再送一次，回一樣的內容，沒有寫入任何東西。
  • 故障 E。密語改錯，回 403；Executions 沒有這一筆，子流程也沒被呼叫。
  • 進階。在 Telegram 傳「查 2330」收到回覆；通道網址被打開編輯器的處理，見第 3 段安全提醒（待查證）。
  • 變形題。主線加上自選股限制，不在清單的代號回「這檔不在你的清單」，不是 0 元。
卡關救援
  • 404「The requested webhook "POST m7-quote" is not registered」→ 看是不是用了正式網址 → 用了正式網址卻沒 Publish，或 Publish 後還沒生效，Publish 後等幾秒再試 → 確認改回 200。
  • 測試網址沒反應 → 看有沒有按聽取測試 → 沒按，或聽完一次就停了（待查證），重按再送 → 確認畫布上有資料。
  • 422「Failed to parse request body」→ 看你是不是用 -d 直接帶 JSON → PowerShell 吃掉引號，改用請求檔 --data-binary "@req-2330.json" → 確認回 200。
  • 403「Authorization data is wrong!」→ 看密語和標頭名稱 → 密語或標頭名稱不對（X-Family-Key 大小寫照抄）→ 確認回 200。
  • curl 跳出一堆紅字參數錯誤 → 看打的是不是 curl → 改打 curl.exe → 確認有回 JSON。
  • 「Workflow is not active」→ 看查價子流程 → 沒 Publish，發布它 → 重送一次確認有回價格。
  • 回覆一直「找不到」→ 看代號 → 代號打錯，或是上櫃股票（只查得到上市股票）→ 換成 2330 確認有價格。
  • Telegram 沒反應 → 逐一檢查 ngrok 網址變了、WEBHOOK_URL 沒設或沒重開 n8n、chat ID 沒換、同一個 Bot 有兩個 Telegram 觸發 → 修好後在 Telegram 再傳一次，確認 Executions 有新紀錄。

求助時附 n8n 版本、哪個節點、錯誤訊息原文、已經試過什麼。截圖和貼文字前，先遮住 Bot token、chat ID、密語和 ngrok 網址。
