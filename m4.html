M4｜API、RSS 與排程

每天早上自動抓股價、匯率、警特報、新聞約 2–3 小時先修：M3實測 n8n 2.48.4（2026-11-18）・你的畫面可能略有不同

成果與先修

讓四條流程每天早上收集股價、匯率、警特報與新聞，並能辨認缺資料與來源故障。 先完成 M3。已經會取得 API 與 RSS 資料的人可以從模擬來源故障及真正排程的驗收開始。 不用新帳號，來源免金鑰，主線費用 0 元。股價與匯率只供紀錄與提醒。

白話觀念

HTTP Request 照網址拿資料，回傳 JSON 陣列會自動拆成多個 Item，這次不用另接 Split Out。狀態碼 200 是成功、404 是找不到、503 是對方暫時壞掉。RSS Read 讀新聞與警報的固定格式，一則是一個 Item。Limit 限制筆數。Schedule Trigger 決定何時啟動；存檔後還要 Publish 才會自動跑。Always Output Data 讓空結果仍送出一筆，才能寫「沒有警特報」。跨次去重會記住以前處理過的連結，要用正式排程驗證。

排程 → HTTP Request → Filter／Limit → 整理
排程 → RSS Read → 整理
排程 → RSS Read → Limit → Remove Duplicates → 整理

素材包

  • main-stock-done.json：股價收集完成版。
  • main-fx-done.json：匯率收集完成版。
  • main-warn-done.json：警特報狀態完成版。
  • main-news-done.json：新聞跨次去重完成版。
  • ex1-done.json：出門警報提醒草稿完成版。
  • ex2-done.json：發票開獎提醒完成版。
  • mock-source.json：共用模擬來源，用於空 RSS、缺欄位與 503。

用 Import from File 匯入，位置見版本附頁。本課不用憑證；各流程獨立建立，不要把四條主線串成一條。

四條收集流程的「排程」都用 Schedule Trigger，每天 7 點。先確認流程 Settings 的 Timezone 為 Asia/Taipei，M0 啟動時已設定 GENERIC_TIMEZONE；位置見版本附頁。手動檢查完後按 Publish，只存檔不會上線。本機自架時電腦要開著、n8n 要在跑，睡眠或關機期間不會執行；恢復後是否補跑（待查證）。

股：收集自選股

取得證交所盤後資料，留下台積電與鴻海並整理欄位。

節點 用途 關鍵設定
排程（Schedule Trigger） 每天啟動 每天 7 點
抓股價（HTTP Request） 取得股票陣列 GET，網址如下
挑自選股（Filter） 留下兩檔 Code 字串等於 2330 或 2317，OR
整理（Edit Fields (Set)） 統一日期與型別 下方六個欄位，用 Expression 
https://openapi.twse.com.tw/v1/exchangeReport/STOCK_DAY_ALL

  1. 建立前兩個節點，設定網址與 GET，手動執行檢查來源。 你應該看到：「抓股價」有 1000 筆以上，含 Date、Code、Name、ClosingPrice、Change；數字原本是字串。

  2. 接上「挑自選股」，用 String 的 is equal to 比較 {{ $json.Code }} 與 2330、2317，選 OR。 你應該看到：留下 2 筆，代號是 2330、2317。

卡住了？一筆都沒留下時先確認欄名是大寫 Code，比較值是字串，兩條條件用 OR。

  1. 接上「整理」，依下表新增欄位，選型別並貼入 Expression，執行整條流程。 你應該看到：整理後 2 筆，dataDate 像 2026-11-17，code、name 是字串，有資料時 close、change 是數字。
欄位 型別 值
dataDate String {{ (Number($json.Date.slice(0,3))+1911) + '-' + $json.Date.slice(3,5) + '-' + $json.Date.slice(5,7) }}
code String {{ $json.Code }}
name String {{ $json.Name }}
close Number {{ $json.ClosingPrice === '' ? null : Number($json.ClosingPrice) }}
change Number {{ $json.ClosingPrice === '' ? null : Number($json.Change) }}
valid Boolean {{ $json.ClosingPrice !== '' }}

沿用 M2 的整理方式：收盤空字串時，close、change 都是 null，valid=false，不能相信來源此時填的漲跌零值。早上 7 點取得的是最近一個交易日資料；一般週一早上看到上週五的資料，遇休市要再往前看。早報要寫資料日期，不寫「昨天收盤」。

匯：只取最新一筆

從央行歷史資料取最後一筆，轉成日期與數字匯率。

節點 用途 關鍵設定
排程（Schedule Trigger） 每天啟動 每天 7 點
抓匯率（HTTP Request） 取得央行歷史資料 GET，網址如下
最新一筆（Limit） 取最後一筆 筆數 1，Keep 選 Last Items
整理（Edit Fields (Set)） 整理日期與匯率 下方兩個欄位 
https://cpx.cbc.gov.tw/api/OpenData/FTDOpenData_Day
  1. 建立「排程」與「抓匯率」，設定網址後手動執行，再接上「最新一筆」。Keep 的位置見版本附頁。 你應該看到：來源有 1000 筆以上，為 2008 年起由舊到新的歷史資料；「最新一筆」留下 1 筆。

卡住了？日期還在 2008 年時先把 Keep 從 First Items 改成 Last Items。

  1. 接上「整理」，依下表設定 Expression 並執行，查看日期與數字型別。 你應該看到：1 筆，dataDate 像 2026-11-17、usd 是數字；實際日期與匯率依來源更新。
欄位 型別 值
dataDate String {{ $json['日期'] ? $json['日期'].slice(0,4) + '-' + $json['日期'].slice(4,6) + '-' + $json['日期'].slice(6,8) : null }}
usd Number {{ $json.NTD_USD ? Number($json.NTD_USD) : null }}

先檢查欄位存在才整理，缺欄位給 null，不讓它變成 0。央行匯率是參考資料，不是銀行換匯的成交價。

  1. 暫時把「抓匯率」網址改成 http://localhost:5678/webhook/mock?status=200，重跑，再恢復央行網址。 你應該看到：來源成功回應，但「抓匯率」只有一個 data 欄位（整段回應被當成文字），沒有 日期、NTD_USD；整理後 dataDate=null、usd=null。這是缺資料，沒有報錯。

  2. 暫時改用 http://localhost:5678/webhook/mock?status=503 並重跑，記下失敗節點後恢復央行網址。 你應該看到：「抓匯率」紅色，後面的「最新一筆」與「整理」沒跑。

錯誤訊息為 Service unavailable - try again later or consider setting this node to retry automatically (in the node settings)。錯誤不會被當成資料往下傳，重試留到 M6。

https://www.cwa.gov.tw/rss/Data/cwa_warning.xml
  1. 建立前三個節點，在「抓警特報」的節點 Settings 開啟 Always Output Data，依下表設定「整理」。位置見版本附頁。 你應該看到：「整理」至少 1 筆，status 是 warning 或 none；有警特報時保留來源標題。

title String {{ $json.title ?? '目前沒有警特報' }}
  1. 暫時把來源改成 http://localhost:5678/webhook/mock?kind=rss_empty，重跑，再關閉 Always Output Data 重跑比較。 你應該看到：開啟時空資料 1 筆可整理成 status="none"；關閉時輸出 0 筆，後面不跑也不報錯。

聞：只留下以前沒處理過的新聞

從行政院新聞取前五則，再以連結判斷是否處理過。

節點 用途 關鍵設定
排程（Schedule Trigger） 每天啟動 每天 7 點
抓新聞（RSS Read） 讀取行政院本院新聞 網址如下
取前5則（Limit） 限制則數 筆數 5，Keep 為 First Items
新的才留（Remove Duplicates） 跨次比對連結 Remove Items Processed in Previous Executions，值 {{ $json.link }}
整理（Edit Fields (Set)） 留下標題、連結與發布時間 三個欄位都用 String 
https://www.ey.gov.tw/RSS_Content.aspx?ModuleType=3

  1. 建立前四個節點並連線，設定網址、前 5 則與跨次去重操作，再手動執行。位置見版本附頁。 你應該看到：「取前5則」5 筆；全新流程手動測試「新的才留」也是 5 筆。

  2. 接上「整理」，新增 title＝{{ $json.title }}、link＝{{ $json.link }}、pubDate＝{{ $json.isoDate }}，全部選 String 與 Expression。 你應該看到：5 筆，每筆含標題、行政院新聞連結與發布時間；內容依當時來源變動。

小練習①：出門看警報

只在有颱風、豪雨或強風的警特報時產生提醒草稿。

節點 用途 關鍵設定
排程（Schedule Trigger） 每天檢查 每天 7 點
抓警特報（RSS Read） 讀取警特報 氣象署網址；不開 Always Output Data
挑關鍵字（Filter） 留下相關警報 title contains 颱風／豪雨／強風，OR
提醒草稿（Edit Fields (Set)） 組提醒文字 text 與 link 都用 String

卡住了？有符合標題卻沒通過時先看是否誤選 AND，改用 OR 再比對同一次輸入。

  1. 接上「提醒草稿」，text 填 {{ '出門注意：' + $json.title }}、link 填 {{ $json.link }}，切換 Expression 後重跑。 你應該看到：有符合警報才有草稿，text 以「出門注意：」開頭並附來源連結；沒有時不產生草稿。

小練習②：發票開獎提醒

單數月 25 日傍晚讀最新一期發票 RSS，依公布時間產生提醒文字。

節點 用途 關鍵設定
排程（Schedule Trigger） 指定開獎後檢查時間 Custom (Cron)：0 18 25 1,3,5,7,9,11 *
抓發票（RSS Read） 讀取最新期別 https://invoice.etax.nat.gov.tw/invoice.xml
最新一期（Limit） 只取第一則 筆數 1，Keep 選 First Items
對獎提醒（Edit Fields (Set)） 判斷是否剛公布 依下表設定三個欄位
  1. 建立前三個節點，將「排程」設為 Custom (Cron) 並填入表中內容，手動檢查 RSS 與第一則資料。位置見版本附頁。 你應該看到：「最新一期」1 筆，含來源的 title、link、isoDate。

Cron 的五格依序是「分 時 日 月 星期」；這行代表單數月 25 日 18:00。已實測匯入與 Publish，實際到點觸發（待查證）。

  1. 接上「對獎提醒」，依下表新增欄位，選型別並切換 Expression。 你應該看到：period 是來源期別字串、fresh 是布林值，text 有開獎提醒或待更新文字。
欄位 型別 值
period String {{ $json.title }}
fresh Boolean {{ $now.diff(DateTime.fromISO($json.isoDate), 'days').days < 3 }}
text String {{ $now.diff(DateTime.fromISO($json.isoDate), 'days').days < 3 ? '發票 ' + $json.title + ' 開獎了：' + $json.link : '最新一期還是 ' + $json.title + '，新一期可能還沒公布' }}

DateTime 是 n8n 內建日期工具，這裡用來算距離公布幾天。RSS 第一則是最新一期；公布不到 3 天視為剛開獎，超過就說官網可能還沒更新，只說待更新，不編造新一期號碼。本課不做自動對獎。

卡住了？看起來仍是上一期時先查看來源標題與 isoDate，不要自己把期別換成想像的新一期。

  1. 執行整條流程，核對三個欄位與來源，再確認時區後 Publish。 你應該看到：1 筆，期別是來源格式（例如 115年 07~08月），fresh 沒有引號，提醒保留來源期別。

看懂執行紀錄

打開 Executions 檢查執行時間與啟動方式，分辨手動測試與排程自行啟動，位置見版本附頁。交出一次排程自己跑出的紀錄，不能拿手動執行代替；發票 Cron 是否實際到點觸發仍待查證。

股價看來源 1000 筆以上、篩選 2 筆與整理 2 筆，逐筆檢查日期與型別。匯率看來源多筆、限制後 1 筆及整理後 1 筆。警特報看 status，空來源仍有 none 才符合早報需求。新聞要比較兩次正式排程的連結與去重筆數，0 筆後沒跑整理是正常結果。

503 測試要記錄「抓匯率」的紅色錯誤與原文，再確認後面沒有執行。200 缺欄位則是成功執行但值為 null，兩者不同；不能只看綠燈判斷資料完整。

驗收

  • 正常 N。四條主線各自取得真實來源；股價 2 筆、匯率 1 筆，核對來源資料日期，新聞有標題與連結；沒有警特報時 status=none 也正常。
  • 正常排程。確認 Timezone 為 Asia/Taipei，流程已 Publish，交出至少一次排程自行執行的紀錄與時間。
  • 缺資料 M。匯率來源暫換 http://localhost:5678/webhook/mock?status=200，確認 dataDate、usd 都是 null，不是 0，也不是故障。
  • 空 RSS。主線警特報暫換 http://localhost:5678/webhook/mock?kind=rss_empty；開啟 Always Output Data 時得到 none，關閉時後面不跑也不報錯；測完主線重新開啟。
  • 重複 D。新聞 Publish 後讓排程跑兩次，第二次「新的才留」變少，沒有新連結時是 0 筆；解釋手動執行為何無法建立歷史。
  • 故障 E。匯率來源暫換 http://localhost:5678/webhook/mock?status=503，確認「抓匯率」紅色、整理沒跑，沒有把錯誤當成匯率。
  • 恢復。把所有模擬網址改回各自真實來源，新聞測試排程恢復每天 7 點並重新 Publish。
  • 變形題。複製「匯」流程改成每天 8 點；在整理後加欄位節點並保留其他欄位，以 Number 新增 usdBudget：{{ $json.usd > 0 ? Math.round(30000 / $json.usd * 100) / 100 : null }}。可換自己的台幣預算，並寫一句「這不是銀行換匯價」。
卡關救援
  • 時間到沒跑 → 看 Publish 狀態、流程時區及 Executions → 先確認 Asia/Taipei、電腦沒睡眠、n8n 正在跑 → 等下一次排程並確認有正式執行紀錄；錯過是否補跑（待查證）。
  • 匯率有 4,000 多筆或日期是 2008 年 → 看「最新一筆」的 Limit 與 Keep → 先設 1 筆、Last Items → 確認整理只剩 1 筆且日期對應來源最後一筆。
  • 警特報後面都沒跑 → 看 RSS 筆數與節點 Settings → 主線先開 Always Output Data → 用空 RSS 確認 none；出門提醒練習不開，0 則不提醒是正常的。
  • 新聞每次全部出現 → 看紀錄是否手動執行及去重操作 → 先選跨次操作，以正式排程跑兩次 → 確認第二輪只剩新的連結或 0 筆。
  • 模擬來源回 404 → 看模擬來源是否已 Publish → 先發布、等幾秒再試 → 確認回預期的 200 或 503；指令發布有實測延遲，編輯器按 Publish 是否立即生效（待查證）。
  • 證交所日期不是今天 → 看來源 Date 與交易日 → 先確認假日或來源尚未更新 → 核對整理保留來源日期，不自行改成今天。
  • 來源回應很慢 → 看失敗節點與錯誤原文 → 先確認網址與來源狀態，可用 http://localhost:5678/webhook/mock?delay=3 比較等待 3 秒的情況 → 確認收到回應；逾時設定在 M6 再教。
