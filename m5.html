M5｜通知、憑證與檔案

早報傳到 Telegram，數字記進 Excel約 3 小時先修：M4實測 n8n 2.48.4（2026-11-18）・你的畫面可能略有不同

成果與先修

每天早上手機收到一則「生活早報」（Telegram），當天的股價與匯率另存成一個 Excel 檔。 先完成 M4。已經有 Telegram Bot 與 Bot token 的人可以從「第 1 段」開始；已經會用憑證與子流程的人可以快速帶過第 1–3 段，但四條收集流程都要執行過，snap 裡有快照檔，第 4 段才讀得到。 要準備 Telegram 帳號（手機號碼註冊，免費）；小練習②二選一，LINE 路線要 LINE 帳號，Google 關卡要 Google 帳號。主線費用 0 元；LINE 免費方案的推播則數與是否要綁信用卡以你的後台顯示為準（待查證）。時間約 3 小時，主線約 2.5 小時，支線另計。股價與匯率只供紀錄與提醒。

白話觀念

Credential（憑證） 像把鑰匙放進 n8n 的保險箱，流程只寫「用哪一把」；匯出或分享流程 JSON 不會帶出鑰匙，所以匯入素材後要自己選憑證。Bot token、LINE token 只能貼在 Credential，不准貼進流程欄位、截圖或聊天訊息；外洩就到原平台重新發一把。子流程 是寫一次、讓很多流程呼叫的小流程；本課只教「呼叫寫好的」，要先 Publish 才能被呼叫。快照檔 是每條收集流程把結果存成的一個 CSV（同名覆蓋，只留最新），早報和 Excel 再去讀；某條來源壞了，其他照常，早報也能標出哪一行是舊的。n8n 只准讀寫 .n8n-files 資料夾（Docker 容器裡是 /home/node/.n8n-files，Windows 是 C:\Users\<你>\.n8n-files），超出範圍會報「Access to the file is not allowed.」。

主線沒有一條長流程，而是 7 條小流程分工：

股、匯、警、聞（7:00）→ 存快照（呼叫子流程）→ snap/stock.csv、fx.csv…
每日 Excel（7:10）：讀 stock、fx 快照 → 轉數字 → 存成 daily/日期.xlsx
早報（7:10）：讀全部快照 → 合成一筆 → Telegram

素材包

  • sub-snapshot-done.json：快照寫入子流程（3 節點）。
  • main-stock-done.json：「股」收集流程，已改成存快照。
  • main-fx-done.json：「匯」收集流程，已改成存快照。
  • main-warn-done.json：「警」收集流程，已改成存快照。
  • main-news-done.json：「聞」收集流程，取前 3 則並存快照。
  • main-excel-done.json：每日 Excel 流程。
  • main-report-done.json：早報傳到 Telegram 的流程。
  • ex1-done.json：吃藥時間提醒（Telegram）。
  • ex2-line-done.json：推播到 LINE（LINE 路線）。
  • ex2-google-done.json：寫進 Google 試算表（Google 關卡）。
  • data-old-fx.csv：舊的匯率快照，驗收「舊資料」用。

用 Import from File 匯入，位置見版本附頁。匯入後要自己選憑證；有呼叫子流程的流程，要在「存快照」重新選子流程（素材裡是空的）。

主線：早報傳到 Telegram、數字記進 Excel

先做準備，再依序完成五小段：快照寫入子流程、改「匯」、匯入股警聞、每日 Excel、早報。

準備：資料夾與 Telegram

  1. 建資料夾：在 C:\Users\<你>\.n8n-files 底下建 snap、daily 兩個資料夾。實測：Windows 上 n8n 不會自動建子資料夾，沒建會報「The file or directory does not exist」。 你應該看到：.n8n-files 底下有 snap、daily 兩個空資料夾。

  2. 用 Docker 的人，要讓容器看得到這個資料夾：關掉 n8n，把 M0 的 docker run 指令加上一段 -v（PowerShell 寫法）後重新啟動。不掛載的話，檔案會寫在容器裡，Windows 資料夾看不到。

    docker run -it --rm --name n8n -p 5678:5678 -e GENERIC_TIMEZONE=Asia/Taipei -e TZ=Asia/Taipei -v n8n_data:/home/node/.n8n -v "$env:USERPROFILE\.n8n-files:/home/node/.n8n-files" docker.n8n.io/n8nio/n8n

    你應該看到：n8n 正常啟動，之後寫出的檔案會出現在 Windows 的 .n8n-files\snap。本機沒有 Docker，掛載的實際效果與容器是否自動建資料夾（待查證）。

  3. 用 npx 的人：素材裡的路徑是 Docker 的 /home/node/.n8n-files/...，要換成 C:/Users/<你>/.n8n-files/...。要改的節點：子流程「寫檔」、每日 Excel 的「讀快照」「寫檔」、早報「讀快照」、Google 分頁「讀快照」。 你應該看到：這五個節點的路徑都以你自己的 C:/Users/<你>/.n8n-files/ 開頭。

卡住了？報「Access to the file is not allowed.」先確認路徑在 .n8n-files 裡，npx 使用者確認有換掉路徑。

  1. 第一次用 Telegram：
    • 手機裝 Telegram App（免費，手機號碼註冊）。
    • 找官方的 @BotFather，傳 /newbot，照提示取名，拿到 Bot token。
    • 在 Telegram 找到自己的 Bot，按 Start。沒先開對話，Bot 不能傳訊息給你。
    • 取得自己的 chat ID：瀏覽器開 https://api.telegram.org/bot<你的 Bot Token>/getUpdates，在回應裡找 "chat":{"id":數字。這個網址含 token，看完關掉，不要分享。
    • 在 n8n 新增 Telegram API 憑證，貼上 token，位置見版本附頁。 你應該看到：n8n 的憑證清單多了一把 Telegram 憑證，你手上有一個 chat ID（數字）。App 畫面與 getUpdates 回空的原因（待查證）。

卡住了？getUpdates 回應是空的時先確認你已經對自己的 Bot 按過 Start 並傳過一句話；仍是空的原因（待查證）。

第 1 段：匯入快照寫入子流程

這個子流程負責把收到的資料存成一個 CSV 檔，之後四條收集流程都呼叫它。

節點 用途 關鍵設定
子流程入口（Execute Workflow Trigger） 收下呼叫端交來的全部資料 輸入選 Accept all data
轉成CSV（Convert to File） 把多筆資料變成一個 CSV 檔 格式 CSV，會自動加 BOM，Excel 開中文不亂碼
寫檔（Read/Write Files from Disk） 寫到快照資料夾 Write，路徑如下 
/home/node/.n8n-files/snap/{{ $('子流程入口').first().json.kind }}.csv

  1. 匯入 sub-snapshot-done.json，確認三個節點與上表一致。 你應該看到：3 個節點依序連線；npx 使用者已換成自己的路徑。

  2. 看懂檔名那一行：為什麼不寫 $json.kind？實測：資料轉成檔案之後，原本的欄位就不在 $json 裡了，寫 $json.kind 會得到一個沒有名字的 .csv。所以要「回頭拿前面節點的資料」：$('子流程入口').first().json.kind 是去「子流程入口」拿第一筆的 kind。

  3. 按 Publish，不用按執行，它要等別人呼叫。Publish 後要等幾秒才生效。 你應該看到：流程列表裡它顯示已發布，位置見版本附頁。

卡住了？之後呼叫時報「Workflow is not active and cannot be executed.」，先確認有 Publish，剛發布就等幾秒再跑。

第 2 段：把「匯」改成存快照

從 M4 的「匯」流程開始自己動手改，main-fx-done.json 當對照。「整理」改成 6 個快照欄位，最後加一個「存快照」。共 5 個節點：排程 → 抓匯率 → 最新一筆 → 整理 → 存快照。

節點 用途 關鍵設定
排程（Schedule Trigger） 每天啟動 每天 7 點
抓匯率（HTTP Request） 取得央行歷史資料 沿用 M4
最新一筆（Limit） 取最後一筆 筆數 1，Last Items
整理（Edit Fields (Set)） 整理成 6 個快照欄位 下方欄位表
存快照（Execute Sub-workflow） 呼叫子流程存檔 從清單選「M5 快照寫入」，搜尋名稱見版本附頁

四條收集流程共用同一組快照欄位：

欄位 型別 意思
kind String 哪一種：stock、fx、warn、news，也是檔名
label String 早報上顯示的名字
value Number 數字（股價、匯率）；沒有數字的來源是 null
dataDate String 資料日期，不是抓取日期
status String ok、missing（資料不足）、warning／none（有沒有警特報）
fetchedAt String 抓取時間，早報用它判斷是不是舊資料

「匯」的六個欄位 Expression：

欄位 值
kind fx
label 美元
value {{ $json.NTD_USD ? Number($json.NTD_USD) : null }}
dataDate {{ $json['日期'] ? $json['日期'].slice(0,4) + '-' + $json['日期'].slice(4,6) + '-' + $json['日期'].slice(6,8) : null }}
status {{ $json.NTD_USD ? 'ok' : 'missing' }}
fetchedAt {{ $now.toISO() }}

缺資料時 value 是 null、status 是 missing，不寫 0（沿用 M2–M4）。

  1. 把「整理」改成上面六個欄位，後面接「存快照」，在「存快照」選「M5 快照寫入」。執行整條流程。 你應該看到：「存快照」1 筆，fileName 結尾是 /snap/fx.csv；用記事本打開 snap\fx.csv：第一行是欄名，第二行是美元那一筆。

卡住了？「存快照」沒有子流程可選，或執行報找不到流程：先確認快照寫入子流程已 Publish，再回「存快照」重新選一次。

第 3 段：匯入股、警、聞三條

三條都是 M4 的流程換上快照欄位加存快照：股 5 節點、警 4 節點、聞 5 節點。匯入後每條的「存快照」都要重新選「M5 快照寫入」。

三條的 kind 分別是 stock、warn、news，value 欄位在警、聞是 {{ null }}，其他欄位照下表：

欄位 股 警 聞
label {{ $json.Name + ' 收盤' }} {{ $json.title ?? '目前沒有警特報' }} {{ $json.title }}
value {{ $json.ClosingPrice === '' ? null : Number($json.ClosingPrice) }} {{ null }} {{ null }}
dataDate {{ (Number($json.Date.slice(0,3)) + 1911) + '-' + $json.Date.slice(3,5) + '-' + $json.Date.slice(5,7) }} {{ $json.isoDate ? $json.isoDate.slice(0,10) : null }} {{ $json.isoDate ? $json.isoDate.slice(0,10) : null }}
status {{ $json.ClosingPrice === '' ? 'missing' : 'ok' }} {{ $json.title ? 'warning' : 'none' }} ok
fetchedAt {{ $now.toISO() }} {{ $now.toISO() }} {{ $now.toISO() }}

跟 M4 不同的地方：

  • 「股」的「挑自選股」素材寫成一個條件 {{ ['2330','2317'].includes($json.Code) }} 為 true，效果和 M4 的兩條 OR 相同。
  • 「聞」改成「取前3則」（Limit），拿掉跨次去重。理由：早報每天列最新 3 則頭條就好；M4 的「新的才留」適合「有新的才通知」，用在快照會讓沒新聞的日子留著舊檔。M8 的 AI 摘要也是 3 則。
  • 「警」的「抓警特報」保留 M4 的 Always Output Data，沒有警特報也要有一行狀態。

  1. 匯入 main-stock-done.json、main-warn-done.json、main-news-done.json，各自在「存快照」選「M5 快照寫入」。 你應該看到：三條流程的「存快照」都沒有紅色警示。

  2. 三條各執行一次。 你應該看到：snap 資料夾裡有 fx.csv、news.csv、stock.csv、warn.csv 四個檔；股的「整理」2 筆、聞的「整理」3 筆、警至少 1 筆（沒有警特報時是「目前沒有警特報」）。

卡住了？snap 裡出現一個叫 .csv 的檔，是子流程「寫檔」路徑用了 $json.kind，改回第 1 段的寫法。

第 5 段：早報傳到 Telegram

把所有快照合成一筆，組成一則文字傳到手機。

節點 用途 關鍵設定
排程（Schedule Trigger） 每天啟動 每天 7:10
讀快照（Read/Write Files from Disk） 一次讀全部快照 Read，路徑 /home/node/.n8n-files/snap/*.csv
解開CSV（Extract from File） CSV 變回多筆資料 格式 CSV，打開 Exclude Byte Order Mark (BOM)
合成一筆（Aggregate） 很多筆收成一筆 All Item Data，結果放在 data 清單
傳到Telegram（Telegram） 傳出早報 選憑證、填 chat ID、Append n8n Attribution 關掉

訊息文字的 Expression（照抄素材）：

{{ '生活早報 ' + $now.toFormat('yyyy-MM-dd') + '\n' + $json.data.map(r => '・' + r.label + (r.value ? ' ' + r.value : '') + (r.status === 'missing' ? ' 資料不足' : '') + (r.dataDate ? '（' + r.dataDate + '）' : '') + ((r.fetchedAt || '').startsWith($now.toFormat('yyyy-MM-dd')) ? '' : ' ⚠舊資料')).join('\n') }}

拆成幾塊來看：

  • '生活早報 ' + $now.toFormat('yyyy-MM-dd')：開頭標題加今天日期。
  • $json.data.map(r => …)：「每一筆變成一行」，r 代表其中一筆快照。
  • (r.value ? ' ' + r.value : '')：有數字才加數字。
  • r.status === 'missing' ? ' 資料不足' : ''：缺資料就寫「資料不足」。
  • (r.dataDate ? '（' + r.dataDate + '）' : '')：有資料日期就加括號。
  • fetchedAt 不是今天就加「⚠舊資料」：判斷這份快照是不是今天抓的。
  • .join('\n')：每行之間換行。'\n' 是反斜線加 n，不能在引號裡真的按 Enter，實測會報 invalid syntax。

行的順序照檔名排（fx、news、stock、warn），變形題可以改。早報範例：

生活早報 〔今天日期〕
・美元 〔匯率〕（〔資料日期〕）
・〔新聞標題〕（〔資料日期〕）
・〔股名〕 收盤 〔股價〕（〔資料日期〕）
・〔警特報標題或「目前沒有警特報」〕（〔資料日期〕）

小練習②：推播到 LINE 或寫進 Google

二選一：LINE 路線練習推播給自己；Google 關卡練習把快照數字寫進試算表。兩個分頁都要經歷「申請憑證」這一關，選一個做就好。

分頁：LINE 路線

用 LINE 官方帳號的 Messaging API 傳一則訊息給自己。

節點 用途 關鍵設定
手動（Manual Trigger） 手動啟動 無
提醒內容（Edit Fields (Set)） 準備文字與收件人 text、to（你的 userId），都用 String
推播到LINE（HTTP Request） 呼叫 LINE 推播 POST https://api.line.me/v2/bot/message/push，驗證用 Header Auth 憑證，JSON 內容照抄素材

人工設定約 8 步，介面位置一律（待查證）：

  1. 用 LINE 帳號登入 LINE Developers。
  2. 建 Provider。
  3. 建 LINE 官方帳號並啟用 Messaging API。
  4. 在後台發行 Channel access token（長期）。
  5. 找到自己的 userId，後台位置（待查證）。
  6. 用手機掃 QR code，把官方帳號加為好友。
  7. 在 n8n 新增 Header Auth 憑證：Name 填 Authorization，Value 填 Bearer <你的 Channel access token>，Bearer 後面一個空格。位置見版本附頁。
  8. 把 userId 貼進「提醒內容」的 to。

不需要 Webhook。不要用 LINE Notify：它已在 2025-03-31 停止服務，n8n 內建的 Line 節點是 Notify 用的，也不能用。免費方案每月推播則數有上限，push 會算進去，則數與要不要綁信用卡以你後台顯示為準（待查證）。

  1. 匯入 ex2-line-done.json，在「推播到LINE」選你的 Header Auth 憑證，在「提醒內容」填 to。 你應該看到：3 個節點依序連線，推播到LINE 沒有紅色警示。

  2. 手動執行。 你應該看到：LINE 收到「這是 n8n 推播給自己的測試訊息」。

卡住了？錯誤「Authorization failed - please check your credentials」，詳細訊息「Authentication failed. Confirm that the access token in the authorization header is valid.」，是 token 無效（用假 token 實測），回憑證檢查 Value。userId 錯誤時的訊息（待查證）。

分頁：Google 關卡

把快照裡的股價與匯率寫進 Google 試算表。

節點 用途 關鍵設定
手動（Manual Trigger） 手動啟動 無
讀快照（Read/Write Files from Disk） 讀兩個快照檔 Read，/home/node/.n8n-files/snap/{stock,fx}.csv
解開CSV（Extract from File） CSV 變回多筆資料 格式 CSV，打開 Exclude Byte Order Mark (BOM)
寫進試算表（Google Sheets） 新增資料列 Append Row，欄位自動對應

先在 Google 試算表建一張測試表，第一列打上 kind,label,value,dataDate,status,fetchedAt 六個欄名（逗號處分欄）。

OAuth 救援站，5 步，介面位置一律（待查證）：

  1. 在 Google Cloud 主控台建專案。
  2. 啟用 Google Sheets API；是否還要 Google Drive API（待查證）。
  3. 設定 OAuth 同意畫面，類型選 External，把自己加成測試使用者。
  4. 建 OAuth 用戶端（網頁應用程式），把 n8n 憑證頁顯示的 OAuth Redirect URL 逐字貼進「已授權的重新導向 URI」。
  5. 把用戶端 ID 與密鑰貼回 n8n，按 Sign in with Google。

測試模式的授權大約 7 天會失效，失效就回憑證頁重新 Sign in with Google。不用開啟計費。

  1. 匯入 ex2-google-done.json，在「寫進試算表」選你的 Google 憑證、文件與工作表，路徑換成 npx 版的人要改「讀快照」。位置見版本附頁。 你應該看到：4 個節點依序連線，寫進試算表沒有紅色警示。

看懂執行紀錄

打開 Executions。呼叫端和子流程在 Executions 是兩筆分開的紀錄；子流程出錯時，呼叫端的「存快照」也會紅，要兩筆都看。

讀檔節點一個檔＝一筆，解開CSV 一列＝一筆。每日 Excel 看讀快照 2 筆、解開CSV 3 筆、轉數字 3 筆、寫檔 1 筆；早報看讀快照至少 4 筆、合成一筆 1 筆，並點開傳到Telegram 檢查文字裡沒有 undefined。

Telegram、LINE 失敗時節點是紅色的，沒有送出就不算成功；手機有沒有收到，要和紀錄一起看。不能只看有沒有綠燈。

驗收

  • 正常 N。手機收到早報，股價與匯率每行有資料日期；今天的 Excel 打得開，value 是數字、可以加總。
  • 缺資料 M。把「匯」的抓匯率網址暫時換成 http://localhost:5678/webhook/mock?status=200，執行「匯」再執行「早報」，美元那行是「・美元 資料不足」，不是 0。測完網址改回，重跑「匯」。
  • 舊資料。把 data-old-fx.csv 複製到 snap 資料夾、改名成 fx.csv 覆蓋，執行早報，美元那行後面有「⚠舊資料」。測完重跑「匯」。
  • 重跑 D。早報手動執行兩次，手機收到兩則。本課沒有防重送，正式上線靠排程一天一次，不要宣稱已經去重。
  • 故障 E①。把 Telegram 憑證的 token 故意改錯一個字，執行早報，傳到Telegram 變紅，錯誤「Authorization failed - please check your credentials」（用假 token 實測，詳細訊息是 Unauthorized），手機沒收到。測完改回。
  • 故障 E②。把子流程「寫檔」路徑暫時改成 /home/node/test.csv（允許區外），執行「匯」，報「Access to the file is not allowed.」。測完改回。
  • 支線。你選的分頁也要交 N 和 E：LINE 交假 token 的錯誤；Google 交「憑證頁中斷連線再執行」的錯誤（訊息待查證）。
  • 變形題。改早報版面：例如把警特報那行放最前面、改標題文字；缺資料仍要顯示「資料不足」、舊資料仍要有標記。
卡關救援
  • 「Access to the file is not allowed.」→ 看路徑 → 路徑要在 .n8n-files 裡，npx 使用者要換成自己的路徑 → 重跑確認檔案寫進去。
  • 「The file or directory does not exist」→ 看 .n8n-files 下有沒有 snap、daily → 建好兩個資料夾 → 重跑確認不再報錯。
  • 執行了但 Windows 資料夾裡看不到檔 → 看是不是 Docker 沒掛載（待查證）→ 照準備第 2 步加 -v 重新啟動 → 重跑確認檔案出現在資料夾。
  • 「Workflow is not active and cannot be executed.」→ 看子流程是否已 Publish → 發布子流程，剛發布等幾秒再跑（實測）→ 確認存快照成功。
  • 存快照沒有子流程可選、或執行報找不到流程 → 看「存快照」的子流程欄位 → 匯入後要重新選「M5 快照寫入」→ 確認子流程那筆紀錄出現。
  • snap 裡出現一個叫 .csv 的檔 → 看子流程「寫檔」路徑 → 路徑用了 $json.kind，改成 $('子流程入口').first().json.kind → 刪掉怪檔後重跑。
  • 早報或 Excel 讀不到 kind、第一欄名稱前面多一個看不見的字 → 看「解開CSV」 → 打開 Exclude Byte Order Mark (BOM) → 確認欄名正確。
  • 轉數字報「'value' expects a number but we got 'NaN'」→ 看「轉數字」的 Expression → 改成素材的 $json.value ? Number($json.value) : null，不要用 === '' → 重跑確認通過。
  • Excel 裡數字靠左、不能加總 → 看流程有沒有「轉數字」 → 補上這個節點 → 重新產生今天的檔。
  • Expression 報「invalid syntax」→ 看有沒有在引號裡真的按 Enter → 換行寫成 '\n'（反斜線加 n）→ 重跑確認。
  • 早報出現 undefined → 看 Expression 裡的欄位名稱 → 修正拼字與大小寫 → 重跑確認文字正常。
  • 早報每行都有「⚠舊資料」→ 看 7:00 的收集流程有沒有跑、有沒有失敗 → 去 Executions 檢查並手動重跑 → 確認 fetchedAt 是今天。
  • Telegram 收不到 → 看是否沒先按 Start、chat ID 錯（錯誤訊息待查證）、token 錯（Unauthorized）→ 逐項檢查 → 手動再傳一則確認。

求助時附 n8n 版本、哪個節點、錯誤訊息原文、已經試過什麼。截圖和貼文字前，先遮住 Bot token、LINE token、chat ID 和個資。
