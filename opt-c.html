選修 C｜更多資料來源與工具

監看網頁變動，以及其他進階主題依主題先修：M4、M5實測 n8n 2.48.4（2026-11-18）・你的畫面可能略有不同

成果與先修

做一個「網頁變動監看」：每週一抓行政院的 RSS 頻道總表，跟你最近一次確認過的清單比對，有新增、移除或解析失敗才傳 Telegram，沒變動就不吵你。另外有一節「其他進階主題」，簡介幾個之後可以再學的東西。 先修 M4、M5（排程、HTTP Request、Telegram 憑證）。 要準備的帳號：不用新帳號，通知沿用 M5 的 Telegram。 費用 0 元。時間約 90 分鐘（進階主題依你選的而定）。

白話觀念

  1. 基準：你「最近一次人工確認過」的清單。每次抓到的結果都拿來跟它比，有差別才通知。基準寫在 Code 節點的第一行，你確認變動沒問題，就自己改那一行。這不是自動保存每次版本。
  2. 0 筆 ＝ 沒變：比對後沒有差別，節點就輸出 0 筆，後面的 Telegram 就不會跑。這是故意的，不是壞掉。
  3. 空擷取 ≠ 全部被刪：如果一個頻道都抓不到，多半是網頁改版或抓錯頁，不是 7 個頻道同時被刪。所以程式要另外標成「解析失敗」，不能寫成「7 個都移除」。
  4. 禮貌：每週一次就好；只抓白名單裡的頁面；不抓要登入的網站；蝦皮等購物網站的價格是動態載入、而且有使用條款，不要碰；保留來源連結。n8n 不能幫你操作瀏覽器點按鈕，只能抓網頁原始內容。
每週一早上 → 抓頁面（HTTP Request） → 擷取頻道（HTML） → 比對基準（Code） → 傳通知（Telegram）
                                                               └─ 沒變動：0 筆，到此為止

素材包

  • main-done.json：主線，行政院 RSS 頻道監看（5 節點）。
  • ex1-done.json：小練習，自製網頁測試（4 節點，不用連網）。

用 Import from File 匯入，位置見版本附頁。匯入後要自己補的事：「傳通知」選你的 Telegram 憑證，Chat ID 改成 <你的 Chat ID>。

主線：行政院 RSS 頻道監看

節點 用途 關鍵設定
每週一早上（Schedule Trigger） 每週一早上啟動 Custom (Cron)：0 9 * * 1（週一 9 點）
抓頁面（HTTP Request） 抓行政院 RSS 頻道總表網頁 網址 https://www.ey.gov.tw/Page/5AC44DE3213868A9；回應格式 Text；逾時 20 秒
擷取頻道（HTML，Extract HTML Content） 從網頁裡挑出頻道名稱與連結 CSS selector a[href*='RSS_Content']；names 取文字、links 取 href 屬性，兩個都回傳陣列
比對基準（Code） 跟基準比，決定要不要通知 只改第一行 baseline；程式的做法見下面
傳通知（Telegram） 傳訊息給自己 憑證選你的 Telegram；訊息讀 $json.message

Code 節點是本課第一次用。你不用會寫程式，只要會改第一行的 baseline（基準清單）。程式做三件事：

  1. 一個頻道都抓不到：輸出 1 筆「解析失敗」。

  2. 跟基準一樣：輸出 0 筆，後面的通知不會跑。

  3. 有不同：輸出 1 筆，列出新增和移除。

  4. 匯入 main-done.json，「傳通知」選你的 Telegram 憑證，Chat ID 改成 <你的 Chat ID>。
    你應該看到5 個節點連成一條線；「比對基準」打開是一段程式，第一行是 baseline，有 7 個頻道名稱。

  5. 按 Execute workflow（不用等週一）。 你應該看到（N）：「抓頁面」1 筆；「擷取頻道」1 筆，names 有 7 個名稱，links 有 7 個網址；「比對基準」0 筆；「傳通知」沒有跑。2026-11-21 實測抓到的 7 個頻道是：消費者保護消費資（警）訊、消費者保護新聞稿、本院新聞、即時新聞澄清（資料來源：各部會）、部會新聞（資料來源：各部會）、院長行程、院會決議，也就是素材裡的基準。

卡住了？「比對基準」有輸出、顯示有變動：先打開「擷取頻道」，把 names 跟基準逐個比，看是網頁真的改了，還是名稱有多一個空白、括號全形半形不同。確認是真的變動，就更新基準那一行。

  1. 打開 Executions，看這一次的紀錄。
    你應該看到手動執行的一筆；各節點的筆數跟上一步一樣，「比對基準」是 0 筆。0 筆不是失敗。

  2. 測 503（E）：把「抓頁面」網址暫時改成 http://localhost:5678/webhook/mock?status=503（M4 的模擬來源，要先 Publish），重跑。
    你應該看到「抓頁面」紅燈，訊息跟 M6、結業範例一樣：「Service unavailable - try again later or consider setting this node to retry automatically」，後面的節點都沒跑。測完把網址改回行政院。

卡住了？改完網址後還是抓到行政院的資料：看有沒有按到存檔，或打開的是不是另一個流程；模擬來源也要先 Publish 並等幾秒。

基準怎麼更新：確認變動是合理的（例如行政院真的新增了頻道）之後，把 baseline 那一行改成新的清單。基準是「最近一次人工確認」，不是自動記住上次的結果。

小練習：自製網頁測試

不連網，自己改一段假網頁，測新增與空擷取兩種情境，不用等行政院改版。

節點 用途 關鍵設定
手動執行（Manual Trigger） 手動啟動 不用設定
假網頁（Edit Fields (Set)） 放一段 HTML，假裝是抓回來的網頁 欄位 html（String），內容是 7 個 <li><a href="…RSS_Content…">名稱</a></li>
擷取頻道（HTML） 同主線，改成讀 html 這個欄位 dataPropertyName 是 html；selector 同主線
比對基準（Code） 同主線 基準同主線

  1. 匯入 ex1-done.json，按 Execute workflow。 你應該看到（N）：「擷取頻道」1 筆，names 有 7 個；「比對基準」0 筆。

  2. 新增：在假網頁的 </ul> 前面多加一個 <li><a href="https://www.ey.gov.tw/RSS_Content.aspx?ModuleType=9">寵物新聞</a></li>，重跑。
    你應該看到「比對基準」1 筆，status: 有變動，added: ["寵物新聞"]，removed: []；訊息是「行政院 RSS 頻道有變動／新增：寵物新聞／移除：無／確認後記得更新基準」（實際分行）。

  3. 空擷取：把假網頁裡的 RSS_Content.aspx 全部換成 Other.aspx（模擬網頁改版，連結不再有 RSS_Content），重跑。
    你應該看到「擷取頻道」的 names 是空陣列；「比對基準」1 筆，status: 解析失敗，訊息「⚠ 行政院 RSS 頻道頁一個頻道都抓不到，可能是網頁改版，請手動打開網頁確認」。不是「7 個都移除」。

卡住了？改完 HTML 「比對基準」仍是 0 筆：先確認改的是「假網頁」的內容，不是別的節點；再看「擷取頻道」的 names 有沒有真的變。

變形題（移除）：從假網頁裡刪掉一個 <li>…</li>，重跑，看 removed 出現哪個名稱；再把基準那一行改成現在這份清單，重跑，確認回到 0 筆。（不附素材，自己改。）

驗收

  • 正常 N。真實網頁沒變：「擷取頻道」names 有 7 個，「比對基準」0 筆，沒有通知。
  • 新增。小練習加一個「寵物新聞」：1 筆，added 是 ["寵物新聞"]，有通知（或在小練習裡看到訊息）。
  • 缺資料（空擷取）。連結不再有 RSS_Content：names 空陣列，標「解析失敗」，說得出為什麼不能說成全部刪除。
  • 故障 503。模擬來源 status=503：「抓頁面」紅燈，後面沒跑；測完改回行政院網址。
  • 變形題。刪掉一個頻道，看到 removed；更新基準後回到 0 筆。
  • 說得出：為什麼每週只抓一次、為什麼不抓購物網站價格、為什麼基準要人工更新。

其他進階主題

下面幾項不附素材、不寫步驟，只讓你知道有這些東西，細節都待查證，要學再另外找官方文件。

  • 氣象署天氣預報：天氣預報資料要先註冊成為會員、取得授權碼（免費），再用 HTTP Request 帶授權碼去抓。申請流程與資料欄位待查證。（待查證）
  • 本機 Ollama：把 AI 模型裝在自己電腦上跑，不用送資料給雲端，也沒有額度問題，但吃電腦效能，要看你的機器夠不夠力。n8n 怎麼接、哪些模型適合待查證。（待查證）
  • Code 節點進階：這課你只改了一行 baseline。想自己寫轉換資料的小程式，可以再學 Code 節點的寫法；先把能用 Edit Fields、If 做到的事用內建節點做，比較好維護。（待查證）
  • n8n 雲端版：n8n 官方有雲端服務，不用自己開電腦跑。方案、價格、資料放在哪裡都待查證；本教材一律用自架的免費版。（待查證）
  • Microsoft 365：n8n 有連 Microsoft 365（例如信件、日曆）的節點，需要微軟帳號與授權。授權方式與限制待查證。（待查證）
卡關救援
  • 通知沒有出現，但流程綠燈 → 打開 Executions 看「比對基準」是不是 0 筆 → 0 筆代表基準與網頁一樣，是正常結果 → 要測通知，用小練習加一個頻道，確認有輸出。
  • 一直說有變動，但看不出差在哪 → 打開「比對基準」輸出的 added／removed → 多半是全形半形、空白字不同 → 把基準改成「擷取頻道」輸出的原樣，重跑確認回到 0 筆。
  • names 是空陣列 → 先看「抓頁面」的回應格式是不是 Text、selector 有沒有打錯 a[href*='RSS_Content']，再手動用瀏覽器打開網頁看結構是否改了 → 修好後重跑；真的改版就要重新找 selector（進階）→ 確認 names 有名稱。
  • 解析失敗的通知一直來 → 看網頁有沒有改版或暫時打不開 → 手動用瀏覽器確認，不要因此去改基準 → 網頁恢復後重跑確認回到 0 筆。
  • 503 或逾時 → 看來源是否暫時故障 → 先不要連續重按，過一陣子再試；需要自動重試回 M6 → 確認再跑會成功。
  • 想拿來監看購物網站價格 → 停 → 動態載入、有使用條款，也需要點按鈕才能看到，n8n 不能操作瀏覽器 → 改用有開放資料的白名單來源。
