結業專題｜生活題庫

獨立完成一個生活流程：改需求、診斷失敗、復原各一次約 4–6 小時先修：M7、M8實測 n8n 2.48.4（2026-11-18）・你的畫面可能略有不同

結業要交什麼

成果：從 12 題生活題庫選一題，自己做出一個能跑的流程，並交出一張驗收紀錄表：正常 N、缺資料 M、故障 E 各一次的證據，加上改需求一次、診斷失敗一次、復原一次。 先修：M7、M8（實際會用到 M2–M6、M9 的東西，題目表會列）。已經很熟 n8n 的人，可以直接看「怎麼選題」挑題，不必讀範例。 要準備的帳號：看你選的題目（下面總表）；大部分只要 Telegram（M5 已建好）。 費用：除了題 10（Gemini 額度，免費額度內 0 元）與題 12（LINE 與 ngrok 條件待查證），都是 0 元。時間約 4–6 小時。

交件一共三樣：

  1. 做好的流程（匯出成 JSON，不含憑證內容）。
  2. 驗收紀錄表：用 final-log.csv 填，用 Excel 開。裡面有 N、M、E、改需求、診斷失敗、復原六列。每列寫：做了什麼、預期是什麼、實際是什麼（筆數或訊息原文）、過了嗎、執行紀錄編號。
  3. 一段話：這次你改了什麼需求、哪裡壞過、怎麼確認修好了。

沒有「做出來」這回事，只有「驗過」。 流程匯入成功、節點全綠，都不算通過；每一種情境都要自己跑，把 Executions 裡看到的筆數和訊息記下來。

⚠️ 金額與個資提醒：股價、匯率只做紀錄與提醒，不是投資建議。題目裡的繳費、帳務、信件都是個資，截圖前遮住；金鑰與 Bot Token 不要寫進流程 JSON 或貼給別人。

怎麼選題

先選你真的用得到的，會比較有動力把壞掉的地方修完。第一次做結業，建議從「易」開始。

範例：旅費匯率提醒

這是題 2 的完整示範：每天早上抓央行匯率，美元低於你設的目標價才傳 Telegram。這題看起來簡單，但裡面有一個真的踩到的坑，後面會用它示範「改需求、診斷、復原」。

節點 用途 關鍵設定
每天早上（Schedule Trigger） 每天定時啟動 每天 8 點
抓匯率（HTTP Request） 抓央行每日匯率 網址 https://cpx.cbc.gov.tw/api/OpenData/FTDOpenData_Day；逾時 20 秒
最新一筆（Limit） 只留最新一天 Keep 選 Last Items，筆數 1
低於目標？（If） 判斷要不要通知 兩個條件都要成立（AND），見下面步驟
傳通知（Telegram） 傳訊息給自己 憑證選你的 Telegram；Chat ID 填 <你的 Chat ID>

位置見版本附頁；排程怎麼設、Telegram 憑證怎麼建，回 M4、M5。

做法：先照做一次

  1. 匯入 main-done.json，「傳通知」選你的 Telegram 憑證，Chat ID 改成 <你的 Chat ID>。
    你應該看到5 個節點，連成一條線；「低於目標？」下面有 true、false 兩個出口，只有 true 接「傳通知」。

  2. 先不管排程，按 Execute workflow。 你應該看到（N）：「抓匯率」輸出 4,692 筆左右（央行把歷史每日資料都回給你）；「最新一筆」1 筆；「低於目標？」走 false，1 筆；「傳通知」沒有跑。2026-11-21 實測當天美元 32.936，目標價預設 30，所以不通知。

卡住了？「抓匯率」逾時或沒資料：先看網址有沒有貼對、逾時有沒有設到 20 秒（資料量大，預設時間可能不夠）。連續失敗就改用 M6 學的重試，不要一直手按。

  1. 改成你自己的目標：打開「低於目標？」，把第二個條件的 30 換成你的目標價。想測通知會不會真的送出，就暫時把 30 改大（例如 40），重跑。
    你應該看到走 true，「傳通知」跑了，Telegram 收到「美元匯率 …（日期 央行資料，不是銀行牌告），低於你設的目標」。測完把目標價改回你的真值，不然每天都會被通知。

  2. 打開 Executions，確認這一次的紀錄筆數與走哪一路，記在驗收紀錄表。
    你應該看到最近一筆是手動執行；各節點的筆數和你剛才看到的一樣。

診斷示範：改需求、壞掉、修好

下面是真的發生過的事，不是編的。照著做一遍，你的驗收紀錄表就有「改需求、診斷失敗、復原」三列。

改需求。 原本的 If 只有一個條件：匯率小於 30。新需求是「來源如果沒回匯率，不能亂通知」，所以要測缺資料。

診斷失敗。

  1. 把「抓匯率」的網址暫時改成 http://localhost:5678/webhook/mock?status=200（M4、M6 用過的模擬來源，要先 Publish；它回 200 但裡面沒有匯率欄位）。
  2. 把「低於目標？」先改成只留一個條件：NTD_USD 小於 30（刪掉「存在」那個條件）。重跑。
    你應該看到走 true，「傳通知」跑了，收到「美元匯率 undefined（undefined 央行資料…）」這種訊息。流程是綠燈、通知也送出去了，但內容是錯的。

卡住了？沒有走到 true：確認「抓匯率」網址真的是模擬來源、且模擬來源流程有 Publish；也確認第二個條件的左邊是 NTD_USD，不是別的欄位。

  1. 找原因。打開「最新一筆」的輸出，沒有 NTD_USD 這個欄位；再打開「低於目標？」，空值被當成「小於 30」，條件成立。
    你應該看到輸入沒有匯率，If 卻判成 true。綠燈不代表對，只有打開輸出才知道。

復原。

  1. 加回第一個條件：NTD_USD 存在（exists），和「小於 30」用 AND 一起成立。
  2. 用模擬來源重跑一次。
    你應該看到走 false，沒有通知。
  3. 把網址改回央行網址，再跑一次 N，確認回到原本的結果（false，1 筆）。
    你應該看到N 的結果跟第 2 步一樣；缺資料那次的紀錄編號也記進驗收紀錄表。

503 故障（E）。 把網址改成 http://localhost:5678/webhook/mock?status=503。
你應該看到「抓匯率」紅燈，訊息「Service unavailable - try again later or consider setting this node to retry automatically」，後面都沒跑。這時要有人知道：M6 的錯誤流程與重試怎麼接，題目交件時至少要證明壞了你會知道。測完改回央行網址。

題目卡

每題先做出 N，再依序測 M、E，最後改一次需求。下面的「建議節點」只是起點，數量和名稱可以自己調；沒寫到的來源網址，回對應模組找（只用白名單來源）。

題 1：自選股盤後雷達

  • 需求：每天盤後讀你的自選股收盤價，只有達到你設的門檻才通知。
  • 建議節點：收集流程（排程、HTTP Request、Split Out、Filter、存檔）＋通知流程（讀檔、If、Telegram…）。M2–M6 的做法照用。
  • N：有一檔達門檻，通知 1 則，內容含代號和價格。M：來源沒回某檔價格，不該用「空值」去比大小（見範例的診斷）。E：模擬 503，要有人被通知。
  • 風險：資料不是即時、不是投資建議；缺值誤算最容易發生。

題 2：旅費匯率提醒

  • 需求：央行匯率低於你設的目標才通知。
  • 建議節點：就是上面的範例。
  • N：不低於目標，不通知。M：模擬來源沒匯率欄位，不通知（診斷示範）。E：503，要有人知道。
  • 風險：這是央行資料，不是銀行實際成交的牌告價。

題 3：出門警特報

  • 需求：氣象署警特報裡，出現你指定的字詞（例如你住的縣市）才通知。
  • 建議節點：排程、RSS Read、Filter（用 contains）、Remove Duplicates（同一則不重複通知）、Telegram。
  • N：有符合的一則，通知 1 則。M：一則都沒有，0 筆、不通知，而且不等於故障。E：來源 503。
  • 風險：零筆不代表安全，這個流程不能保證你不會漏掉警報。

題 4：發票開獎提醒並存檔

  • 需求：新的一期發票開獎資訊出來時通知，並把結果存成檔案。
  • 建議節點：收集流程（排程 Cron、來源、去重、寫檔）＋通知流程。發票的 Cron 在 M4 有做過。
  • N：新的一期，通知 1 則。M：同一期不重複通知。E：來源失敗。
  • 風險：不含載具登入，也不保證自動對獎正確；中獎一定要對官方結果。

題 5：家庭繳費清單提醒

  • 需求：讀本機的繳費清單，快到期的才提醒。
  • 測資：data-bills.csv（4 列：電費重複一筆、瓦斯費沒填到期日）。
  • 建議節點：讀檔、解開 CSV、If 或 Filter（到期日在幾天內）、Telegram。
  • N：快到期的各提醒 1 次。M：瓦斯費沒填到期日，不能算成「0 天到期」，要走另一路並標成「缺資料」。E：讀不到檔案。重複的電費要去重，不然被提醒兩次。
  • 風險：CSV 讀回來全是字串，空格子是「沒有這個欄位」（M5、M9 學過）；帳務是個資；不自動付款。

題 6：家用品補貨（不下單）

  • 需求：庫存低於門檻就提醒，不自動下單。
  • 測資：data-pantry.csv（衛生紙 2／3 低於；洗衣精 1／1 剛好等於；米沒填數量）。
  • 建議節點：讀檔、解開 CSV、Edit Fields（把數量轉成數字）、If、Telegram。
  • N：衛生紙要補。M：米沒填數量，不要默默當成沒事；要有一條路標出「資料缺」。邊界：洗衣精剛好等於，要自己決定算不算低於，再寫進驗收紀錄；改成含等於就是你的「改需求」。E：讀不到檔案。
  • 風險：人工庫存過期、重複採買。

題 7：學習紀錄 Excel

  • 需求：把每天讀書的紀錄整理成 Excel 檔。進階變形：累積成一張總表。
  • 測資：data-study.csv（3 筆，數學沒填分鐘數）。
  • 建議節點：讀檔、解開 CSV、Edit Fields、Convert to File（XLSX）、寫檔。
  • N：3 筆都寫進檔案。M：數學沒填分鐘數，不能算成 0 分鐘又悄悄寫進去；要標出來。E：寫檔的資料夾不存在（M5 的坑）。
  • 風險：檔名被覆寫、Excel 開著檔案時寫不進去。這題不用任何帳號。

題 8：Gmail 購物通知簿

  • 需求：只讀你自己貼了測試標籤的購物通知信，整理後傳到手機。
  • 建議節點：Gmail、Edit Fields、If、Telegram（4 個節點；Google 授權回 M5 的 Google 關卡）。
  • N：有貼標籤的 1 封，整理成 1 則通知。M：沒有符合的信，0 筆。E：授權過期或失效。
  • 風險：信件和訂單是個資，只用測試標籤，不要讀整個信箱；OAuth 會過期。實際節點選項（待查證）。

題 9：出門借車提醒（台北指定站）

  • 需求：出門前查你指定的幾個站，還有車才提醒。
  • 建議節點：排程、HTTP Request、Filter（只留你指定的站）、If、Telegram。資料來源與欄位以白名單為準（待查證）。
  • N：指定站有車，通知 1 則。M：指定站沒有出現在資料裡，要明確說「查不到」，不是「沒有車」。E：來源失敗。
  • 風險：車位隨時在變，資料也可能延遲，提醒只是參考。

題 10：家庭新聞三行摘要

  • 需求：把今天新聞標題做成三行摘要，由你確認後再傳。
  • 建議節點：收集流程（M5 新聞快照）＋ AI 流程（M8 摘要子流程）＋通知流程。
  • N：摘要 ok: true，每行對得回標題。M：沒有標題，不呼叫模型。E：標題夾帶命令（M8 的 E）。
  • 風險：幻覺、提示注入、新聞來源的使用條款；免費額度要看你自己的帳號（待查證）。

題 11：自選股除權息提醒

  • 需求：自選股有除權息時提醒你；股利還沒公告的要標成「待公告」。
  • 建議節點：收集流程（排程、來源、Edit Fields、存檔）＋通知流程（If、Telegram）。
  • N：有除權息的那檔提醒 1 則。M：股利欄位是空的，標成「待公告」，不能當成 0 元。E：來源失敗。
  • 風險：日期是民國年；空欄位；不是投資建議。

題 12：LINE 生活查詢機器人（進階）

  • 需求：你傳「查 2330」給 LINE 官方帳號，機器人回你收盤價。
  • 規模：共 12 個節點（入口 5、查價 4、回覆 3），要分成多條流程；進階題，做不完不影響結業。
  • 要的帳號：LINE 官方帳號與 LINE Developers、ngrok（讓外面連得到你的電腦）；是否免費要看帳號條件（待查證）。
  • 一定要做的安全要求：
    • 驗簽章：確認訊息真的是 LINE 送來的（實際做法與節點待查證）。
    • 只限本人：只回你自己的 userId，別人傳的不理。
    • 處理重送：LINE 可能重送同一個事件，同一個事件不能回兩次。
    • 回覆用的 Channel access token 放在 Credentials，不寫進流程。
  • N：「查 2330」，回 1 則價格。M：「查 9999」查無此代號，回「查不到」。E：簽章錯誤，一律拒絕、不回覆。
  • 風險：reply token 有時效；userId 是個資。這些要求沒做到，不要公開，也不要把 M5 的 push 成功當成「收訊息成功」，兩件事不同。

AI 幫你建的流程也要驗收

如果你請 AI（Claude 或其他）幫你寫流程，驗收規則不會變，還要更嚴：AI 給的流程通常匯入就綠燈，卻不代表邏輯對。

  • 一樣用 N／M／E 三種情境，自己跑，自己看 Executions。
  • 每個節點都要能說出「它在做什麼」，說不出來的就是你還沒懂的地方。
  • 特別測「缺資料」和「打錯欄位」：這兩種常常不會報錯，只是安靜地不提醒（選修 B 有實測）。
  • 不要給 AI 你的真憑證，也不要讓它幫你 Publish。

結業之後

  • 把你的流程維持運作一週，每天看一次 Executions，把壞掉的原因記下來；備份與還原回 M9。
  • n8n 官方有免費的學習課程與徽章（learn.n8n.io），想繼續進階可以去看，內容與費用以網站為準（待查證）。
  • 想再學：選修 A（Agent）、選修 B（讓 AI 幫你寫流程）、選修 C（網頁變動監看與其他主題）。
卡關救援
  • 流程匯入成功、也綠燈，但沒有通知 → 打開 Executions，看 If 走哪一路、每個節點筆數 → 通常是缺資料或欄位打錯，條件被判成 false → 補上「欄位存在」的條件，用 M 情境重跑確認。
  • 通知內容出現 undefined → 看通知節點的 Expression 讀的欄位 → 來源沒給這個欄位，卻照樣往下傳 → 在前面加 exists 條件，重跑確認走 false。
  • 排程沒有跑 → 先確認流程有 Publish、n8n 有開著、電腦沒睡著（M4、M9）→ 到 Executions 看有沒有排程啟動的紀錄 → 補跑後確認有紀錄。
  • 模擬來源沒回應 → 看模擬來源流程有沒有 Publish → 發布後等幾秒 → 再用瀏覽器打開網址確認有回應。
  • 通知重複 → 看有沒有去重（Remove Duplicates）與排程是否設了兩次 → 補上去重或刪掉多的排程 → 連跑兩次確認第二次 0 筆。
  • 做到一半，不知道哪裡改壞了 → 回到上一份備份或匯出的 JSON → 重新匯入比對（M9）→ 確認回到 N 的結果。
