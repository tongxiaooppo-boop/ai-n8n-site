M2｜資料與 Expression

從全部股票資料挑出自選股，日期和數字都轉好約 2 小時先修：M1實測 n8n 2.48.4（2026-11-18）・你的畫面可能略有不同

成果與先修

從股票測資挑出自選股，把民國日期與字串數字轉成可用的欄位。 先完成 M1。已經會使用 Expression 與多筆資料的人可以從驗收的缺資料與重複情境開始。 不用新帳號，主線費用 0 元。使用本頁假想股票測資，金額供紀錄與提醒使用。

白話觀念

一筆資料是一個 Item。一個 Item 裡的陣列可以裝很多筆，先用 Split Out 把陣列拆開，後續節點才會逐筆處理。Filter 讓符合條件的資料通過。If 依條件把資料交到 true 或 false 分支。字串 "2170.00" 要用 Number(...) 轉成數字才能計算，代號 "2330" 保留 String。Expression 的 $json 代表目前這筆資料。缺值以 null 表示，0 則代表真的有數值零。

手動 → 測資陣列（1 Item，data 內 4 筆）→ Split Out（4 Items）→ Filter（2 Items）→ 整理（2 Items）

素材包

  • main-start.json 放好手動與四筆測資陣列。
  • main-done.json 是挑出自選股完成版。
  • ex1-done.json 是旅費換算完成版。
  • ex2-done.json 是家用支出整理完成版。
  • data-normal.json 含兩筆自選股正常資料。
  • data-missing.json 含 2330 收盤價空字串的資料。
  • data-dup.json 含兩筆相同的 2330 資料。

流程檔用 Import from File 匯入，位置見版本附頁。三份 data- 測資檔請開啟後複製全部內容，貼到「測資陣列」的 JSON Output，這個欄位用來填入整份 JSON。

主線：挑出自選股

把四筆股票測資拆開，挑出 2330 與 2317，再整理日期、數字與有效旗標。

節點 用途 關鍵設定
手動（Manual Trigger） 啟動流程 手動執行
測資陣列（Edit Fields (Set)） 放入原始資料 Mode 選 JSON，使用起始版的 {"data":[…]}
拆成多筆（Split Out） 陣列轉多個 Item Fields To Split Out 填 data
挑自選股（Filter） 留下兩檔 $json.Code 的字串值等於 2330 或 2317，條件用 OR
整理（Edit Fields (Set)） 轉日期與數字 依下方六個欄位設定，值用 Expression

  1. 匯入起始版，打開「測資陣列」並執行。核對每筆含 Date、Code、Name、ClosingPrice、Change。
    你應該看到輸出 1 個 Item，data 內有 2330、2317、9999、1101 四筆資料。

  2. 接上 Split Out，命名「拆成多筆」，將 Fields To Split Out 設為 data，再執行整條流程。位置見版本附頁。
    你應該看到「拆成多筆」輸出 4 個 Items，第一筆 Code 為字串 2330。

卡住了？仍只有 1 筆且裡面有陣列時先確認拆分欄位填的是 data，再查看新執行結果。

  1. 接上 Filter，命名「挑自選股」，用兩個 String 的 is equal to 條件比較 {{ $json.Code }} 與 2330、2317，組合選 OR。
    你應該看到「挑自選股」輸出 2 筆，代號依序為 2330、2317。

卡住了？沒有資料通過時先確認比較值採用字串型別，兩個條件使用 OR。

  1. 接上 Edit Fields (Set)，命名「整理」，按 Add Field 逐一新增下表欄位，分別選型別並將值切換 Expression。位置見版本附頁。

    欄位 型別 值
    dataDate String {{ (Number($json.Date.slice(0,3))+1911) + '-' + $json.Date.slice(3,5) + '-' + $json.Date.slice(5,7) }}
    code String {{ $json.Code }}
    name String {{ $json.Name }}
    close Number {{ $json.ClosingPrice === '' ? null : Number($json.ClosingPrice) }}
    change Number {{ $json.ClosingPrice === '' ? null : Number($json.Change) }}
    valid Boolean {{ $json.ClosingPrice !== '' }}

    slice 取出日期的一段，前三碼 115 加 1911 變成西元年 2026。條件 ? A : B 的意思是「條件成立就用 A，不成立就用 B」：收盤價是空字串就給 null，不是空字串才用 Number(...) 轉成數字。收盤價空白時，來源的 Change 可能填 0.0000，此時 close 與 change 都設為 null，valid 為 false。

    你應該看到第一筆預覽日期為 2026-11-17，代號仍是 2330。

  2. 執行整條流程，逐筆查看「整理」的 JSON 輸出與型別。
    你應該看到2 筆，第一筆為 dataDate="2026-11-17"、code="2330"、name="假想甲"、close=2170、change=-45、valid=true。

第二筆應為假想乙，code="2317"、close=219、change=0.5。JSON 中字串有引號，數字與布林值可直接辨認。缺資料驗收時，把測資檔的全部內容貼進「測資陣列」後重跑。

小練習①：旅費換算

把央行格式的日期與匯率字串整理好，計算 30000 元可換算的美元預算。

節點 用途 關鍵設定
手動（Manual Trigger） 啟動流程 手動執行
央行格式（Edit Fields (Set)） 提供測資 日期 為字串 20261117、NTD_USD 為字串 32.85、budgetTwd 為數字 30000
換算（Edit Fields (Set)） 整理並換算 date 用 String，rate、usdBudget 用 Number

  1. 建立新流程，依表加入三個節點並連線，填好「央行格式」後執行。
    你應該看到來源 1 筆，日期與匯率為字串，預算為數字 30000。

  2. 在「換算」新增下表三個欄位，各自選型別並將值切換 Expression。

    欄位 型別 值
    date String {{ $json['日期'].slice(0,4) + '-' + $json['日期'].slice(4,6) + '-' + $json['日期'].slice(6,8) }}
    rate Number {{ Number($json.NTD_USD) }}
    usdBudget Number {{ Math.round($json.budgetTwd / Number($json.NTD_USD) * 100) / 100 }}

    中文欄位名稱在本課使用方括號寫成 $json['日期']。匯率先轉數字，預算除以匯率後乘 100、四捨五入、再除以 100，保留到小數 2 位。

    你應該看到日期預覽為 2026-11-17，美元預算為 913.24。

卡住了？日期取不到時先核對來源欄名「日期」與方括號裡的引號，預算算錯時先檢查 NTD_USD。

  1. 執行整條流程，打開「換算」查看 JSON 輸出。
    你應該看到1 筆，date="2026-11-17"、rate=32.85、usdBudget=913.24。

小練習②：家用支出整理

拆開支出陣列，整理日期與金額，把缺金額的支出送到待補分支。

節點 用途 關鍵設定
手動（Manual Trigger） 啟動流程 手動執行
支出陣列（Edit Fields (Set)） 提供三筆支出 Mode 選 JSON，內容見下方
拆成多筆（Split Out） 拆開陣列 Fields To Split Out 填 rows
整理（Edit Fields (Set)） 統一日期與金額 四個欄位依下表設定
有金額嗎（If） 分成有效與待補 {{ $json.ok }} 選 Boolean 的 is true
  1. 建立前兩個節點，在「支出陣列」的 JSON Output 填入下方內容，執行一次。
    你應該看到1 個 Item 的 rows 內有三筆支出。
{"rows":[{"date":"2026/11/15","item":"衛生紙","amount":"189"},{"date":"2026/11/16","item":"洗衣精","amount":""},{"date":"2026/11/17","item":"牛奶","amount":"95"}]}

  1. 接上「拆成多筆」並填 rows，再接「整理」，按下表新增欄位，值切換 Expression。

    欄位 型別 值
    date String {{ $json.date.replaceAll('/', '-') }}
    item String {{ $json.item }}
    amount Number {{ $json.amount === '' ? null : Number($json.amount) }}
    ok Boolean {{ $json.amount !== '' }}

    你應該看到「整理」有 3 筆，第一筆為 date="2026-11-15"、item="衛生紙"、amount=189、ok=true。

卡住了？洗衣精金額變 0 時先檢查 amount 是否先判斷空字串，再做 Number(...) 轉換。

  1. 接上「有金額嗎」，設定 ok 為真的條件，再執行整條流程，分別查看 true 與 false 分支。
    你應該看到true 2 筆，false 1 筆，false 的洗衣精 amount=null、ok=false。

驗收

  • 正常。主線四筆原始資料拆成 4 個 Items，篩成 2 筆，第一筆日期 2026-11-17、代號字串 2330、價格數字 2170、漲跌數字 -45、valid=true。
  • 正常測資。貼入 data-normal.json，確認拆分與整理都為 2 筆，第二筆代號 2317，並解釋陣列如何變多個 Items。
  • 缺資料。貼入 data-missing.json，確認 1 筆 valid=false，close=null、change=null，兩個缺值都沒有變成 0。
  • 重複。貼入 data-dup.json，確認同一次執行整理後仍有兩筆 2330，M3 才處理去重。
  • 故障。恢復完成版設定，刪掉「整理」中 dataDate 運算式最後的右大括號，執行後找到出錯的節點與欄位，再補回括號重跑成功。
  • 小練習。旅費結果為 913.24，家用支出整理 3 筆，If true 2 筆、false 1 筆，洗衣精金額為 null。

  • 每筆都變成同一檔 → 查看「整理」的 Expression 是否固定引用 $('測資陣列').first() → 先改用 $json 取得目前 Item → 查看第二個 Item，確認代號為 2317。
