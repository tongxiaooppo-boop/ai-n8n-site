M3｜判斷、多筆與合併

漲跌超過門檻才標記，同一則新聞不重複約 2 小時先修：M2實測 n8n 2.48.4（2026-11-18）・你的畫面可能略有不同

成果與先修

把漲跌達門檻的股票送到標記分支，去掉重複新聞，再把兩人的採買清單接起來。 先完成 M2。已經會條件分支與多筆資料的人可以從驗收的重複與故障情境開始。 不用新帳號，主線費用 0 元。股票都是假想測資，只供紀錄與提醒練習。

白話觀念

If 把資料分到 true、false 兩路；Filter 只留下符合條件的資料。Remove Duplicates 用指定欄位辨認重複，這課只比同一次輸入。Merge 的 Append 把兩路資料前後接起來。n8n 通常會處理每個 Item，這三個練習都不用 Loop。例外如 RSS Read 是讀指定網址一次，不是為每筆輸入再讀一次。缺資料用 null，不能當成漲跌為 0。

手動 → 股票陣列 → Split Out → 算漲跌幅 → If（true／false）
手動 → 新聞陣列 → Split Out → Remove Duplicates → Filter
手動 → 兩份清單 → Merge（Append）→ Split Out

素材包

  • main-start.json：主線前三個節點與五筆股票。
  • main-done.json：主線漲跌幅與門檻判斷完成版。
  • ex1-done.json：新聞去重完成版。
  • ex2-done.json：家庭採買合併完成版。
  • data-normal.json：前一日收盤為 95 的正常測資。
  • data-missing.json：收盤與漲跌都缺值的測資。
  • data-dup.json：兩筆同連結新聞的測資。

用 Import from File 匯入流程，位置見版本附頁。測資檔不是流程；開啟後複製整份內容，貼到對應陣列節點的 JSON Output。本課不用憑證。

主線：漲跌超過門檻才標記

從五筆整理後股票計算漲跌幅，挑出漲或跌達 3% 的資料。

節點 用途 關鍵設定
手動（Manual Trigger） 啟動流程 手動執行

超過門檻嗎（If） 分成要標記與不用標記 Boolean 的 is true

  1. 接上「算漲跌幅」，開啟 Include Other Input Fields 保留其他欄位；新增 pct，選 Number，值切換 Expression 並貼上下式。位置見版本附頁。
    你應該看到第一筆仍有 code="2330"、close=2170、change=-45，新增 pct=-2.03。
{{ $json.valid && ($json.close - $json.change) > 0 ? Math.round($json.change / ($json.close - $json.change) * 10000) / 100 : null }}

前一日收盤＝今天收盤 − 漲跌。漲跌幅＝漲跌 ÷ 前一日收盤 × 100，再四捨五入到小數 2 位。資料無效或分母不是正數就給 null，不硬算。

卡住了？代號消失時先開啟保留其他欄位；pct 出現引號時先核對型別是 Number。

  1. 接上「超過門檻嗎」，條件填下式，選 Boolean 的 is true；執行整條流程並分別檢查兩個輸出。
    你應該看到true 2 筆，第一筆 code="3008"、pct=5；false 3 筆，第一筆為 2330。
{{ $json.pct !== null && Math.abs($json.pct) >= 3 }}

Math.abs 是不管正負，只看大小。這裡「漲或跌超過 3%」包含剛好 3%；改條件裡的 3 就能換門檻。true 是要標記的 3008（+5%）、2603（−5%）。false 是 2330（−2.03%）、2317（+0.23%）、9999（無資料）。無資料走 false 不代表沒漲跌，是「不知道」，M5 早報會另外標「資料不足」。

  1. 分別把正常、缺資料測資貼進「整理後股票」，每次替換整份內容後重跑，最後恢復五筆資料。
    你應該看到正常測資 pct=5.26 並走 true；缺資料測資 pct=null 並走 false，沒有變成 0。

小練習①：新聞不重複

用連結辨認同一則新聞，再留下標題含「颱風」的資料。

節點 用途 關鍵設定
手動（Manual Trigger） 啟動流程 手動執行
新聞陣列（Edit Fields (Set)） 提供五筆新聞 Mode 選 JSON
拆成多筆（Split Out） 拆開陣列 Fields To Split Out 填 news

  1. 建立前三個節點，在「新聞陣列」的 JSON Output 填入下方資料，接上拆分後執行。
    你應該看到「拆成多筆」有 5 筆，前兩筆連結都是 https://example.invalid/n1。

  1. 接上「挑字詞」，比較 {{ $json.title }} 是否 contains 颱風，執行並核對連結。

小練習②：家庭採買合併

把阿禾與小嵐的清單前後接起來，再拆成逐項採買資料。

節點 用途 關鍵設定
手動（Manual Trigger） 同時啟動兩路 輸出同時接兩個清單節點
阿禾清單（Edit Fields (Set)） 放阿禾兩項採買 JSON 模式，接合併的 Input 1
小嵐清單（Edit Fields (Set)） 放小嵐三項採買 JSON 模式，接合併的 Input 2
合併（Merge） 接起兩份清單 Append
拆成多筆（Split Out） 拆開兩個清單陣列 Fields To Split Out 填 list
  1. 建立「手動」與兩個清單節點，把手動的同一個輸出分別接到兩個清單，依序填入下方兩份 JSON Output。
    你應該看到阿禾清單輸出 1 個 Item，list 內 2 項；小嵐清單輸出 1 個 Item，list 內 3 項。

阿禾清單：

{"list":[{"item":"衛生紙","qty":1,"who":"阿禾"},{"item":"牛奶","qty":2,"who":"阿禾"}]}

小嵐清單：

{"list":[{"item":"雞蛋","qty":1,"who":"小嵐"},{"item":"牛奶","qty":1,"who":"小嵐"},{"item":"洗碗精","qty":1,"who":"小嵐"}]}
  1. 加入「合併」，阿禾接 Input 1、小嵐接 Input 2，模式選 Append。位置見版本附頁。
    你應該看到「合併」輸出 2 個 Items，各自帶著一個 list 陣列。

卡住了？少一人的清單時先檢查兩個輸入口都有接線，再確認模式是 Append。

  1. 接上「拆成多筆」，指定 list 並執行整條流程，逐筆查看 who。
    你應該看到5 筆，第一筆 item="衛生紙"、qty=1、who="阿禾"，兩人的牛奶各自保留。

Append 就是前後接起來，這課不合併同品項。想一想：要怎麼知道牛奶共買幾瓶？先寫出做法，不用做出來。
